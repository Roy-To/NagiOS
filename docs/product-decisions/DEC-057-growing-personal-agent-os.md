# DEC-057 — 学習・適応・継続によって成長するPersonal Agent OS

**状態:** CONFIRMED（Nagi OS全体の製品コンセプト、利用を通じた個人適応、モデル非依存の継続性、ユーザー主導の訂正・忘却と安全境界、PX-10のB基本方針と将来Cへの高水準拡張方向）／PROVISIONAL（学習品質の評価、対話・状況適応の具体方式・UI・条件、モデル／アルゴリズム、評価方法、実装詳細・提供版・時期）  
**決定日:** 2026-11-16（PX-10追加合意: 2026-11-17）  
**対象:** Nagi OSの中長期的な製品アイデンティティと、0.3 Personal Agent以降のユーザー体験。既存のRelease／Activation Gateおよび実装仕様を変更しない。

## 製品コンセプト（CONFIRMED）

**Nagiは「AIを搭載したOS」にとどまらず、ユーザーと継続的に関わり、許可された経験・作業・フィードバックから学び、ユーザーの目的・好み・習慣への理解と実用上の支援能力を育てていくPersonal Agent OSを目指す。**

Nagiの長期的な価値は、利用開始時点のLLMの一般性能だけではなく、利用者との継続的な関係の中で培われた、**その人の仕事と操作に合わせた理解・提案・作業継続の質**にある。ここで「成長」「相棒」は製品体験を説明する比喩であり、AIの意識・感情・自己目的や人間と同等の主体性を主張しない。

この方針は[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)が既に掲げる、Profile／Memory／Learning／Model Portabilityによる「成長するPersonal Agent OS」を**Nagi OS全体の中核的な製品アイデンティティ**として確認するものであり、0.3へ新たな未承認機能や完了条件を追加するものではない。

## 目指す利用体験と原則（CONFIRMED）

1. **継続利用に応じた個人適応:** Nagiは許可された作業文脈、利用者が採用した提案、繰り返す操作、明示的な指示・訂正などを、DEC-003〜005の範囲で扱う。目的、説明の仕方、作業順序、好みや習慣を徐々に理解し、次回の提案・Contextの選択・作業の再開支援をその人に合わせる。学習を口実に必要のない情報を無差別収集しない。
2. **経験の質を重視:** 単に大量の履歴を保存したり同じ推測を繰り返したりすることを成長とみなさない。利用者による採用・修正・否定と情報の由来を尊重し、誤った理解を訂正できる。習慣は繰り返しと文脈に基づいて判断し、単発操作から勝手に断定しない（DEC-004）。
3. **日常操作とアプリ横断の体験へ反映:** 成長は会話内容の個人化だけに限定しない。Nagiの正規Context／Public Action、Task／Workspace、対応するアプリとの連携を通じ、利用者の作業の探しやすさ、整理、提案、継続性、繰返し作業の改善へ反映する。ただし各機能の具体的な実装・採用条件はそれぞれの決定・承認による。
4. **控えめで実用的な支援:** 利用者の文脈に合った先回りの提案を目指す一方、日常作業を過度に中断せず、DEC-008の積極性設定や通知方針に従う。成長とはAIが権限や主導権を勝手に増やすことではなく、人間にとって適切な支援が増えることを意味する。
5. **モデルと端末を越える連続性:** 利用者の理解を支えるCanonical Memory、Profile、Preferences、Habits、適切なTask／Procedure情報を、特定のLLMの重みやKV cacheから分離してNagi側で管理する。モデル交換や機種更新に際して、保持が許された個人の文脈を原則として継続できる設計を維持する（0.3ロードマップ、DEC-004／013）。端末移行・同期の具体的な方式や対応範囲は既存の別Gateと判断に従う。
6. **利用者が育て方を制御できる:** 何を記憶・利用しているかを確認し、訂正、保護指定、利用停止、明示的な忘却を行える。学習はユーザーの明示指示、元データの分類・所有範囲、正規のPermission／Policy、削除・忘却の規則より優先しない。モデルや端末が変わっても明示的な忘却を破らない。
7. **使わない自由と通常操作の維持:** AIに頼まずGUI／キーボード等で操作できることは変えず、AIが使用できない環境でもOSの通常機能を維持する。自然言語会話、表情・人格演出や特定の対話スタイルを日常操作の前提にしない。

## PX-10 — Nagiの個人化・対話スタイル（2026-11-17／基本方針CONFIRMED）

**基本方針B（CONFIRMED）:** Nagiは、許可された利用経験とフィードバックを通じ、口調・説明量・説明方法などの対話スタイルをユーザーの好みに自然に合わせていく。適応は継続的でも不意に揺れず、安定して理解しやすい対話を目指す。固定人格や擬似感情を要求するものではない。

**将来Cの高水準目標（CONFIRMED）:** Bを基本に、Project／Task／現在の作業状況に応じて対話スタイルをより適切に調整する方向へ将来拡張する。ここで確定したのは製品目標の方向だけであり、実装や提供時期の確約ではない。

**既存CONFIRMEDの維持:** ユーザーの明示的な指示・設定を暗黙の学習・推定より優先する。Profile／Memoryの所有範囲を分離し、モデルを交換しても許可された個人化情報を継続する。ユーザーによる訂正・保護・停止・忘却、機密分類、現在のPermission／Policyも維持する。個人化は新しい情報収集・閲覧・外部送信や権限を許可せず、取得時は既存のUser／Profile／Task ScopeとPermission／Policyを再評価する（DEC-003／004／020／055）。

**PROVISIONAL:** 適応の対象・強さ・更新方法、具体的なUIとユーザー制御、Project／Task／作業状況を参照・判断する条件、利用するモデル・アルゴリズム、評価方法・指標、保存Schema、実装順・提供Version／時期は未決定。

**ロードマップとの関係:** 0.3 Personal Agentの単一Nagi、Profile／model-independent Memoryの既存方向と整合する。将来Cは同一Personal Agentの状況適応目標であり、0.4+ Multi-Agentの導入を意味しない。この追加で0.3／0.4+等への適用Version、Release／Activation／Acceptance Gate、実装状態は変更しない。

## 境界と明示的な非目標

- **成長はLLMの無制限な自己学習・重み更新や、OSの自律的な自己改造を意味しない。** 既存0.3ロードマップのとおり、モデルのファインチューニングを個人Memoryの主要手段とせず、モデル非依存の状態管理を基本とする。
- **Memory・習慣・成功経験は権限ではない。** 学習内容からActionの許可、データ共有、Cloud送信、Workflowの保存・有効化・改訂、他ユーザー情報のアクセス権限を自動的に導かない。各Actionは現行Permission／Capability／Policyと承認済みTask Scopeの正規経路で再評価する（DEC-001／020／028）。
- **自然忘却と明示的な忘却を維持する。** 「長期的な相棒」とは全情報の永久保存を意味しない。原本の削除／アクセス失効、明示忘却、派生Memory、分類・所有ScopeをDEC-003〜005に従って扱う。アプリ内データとユーザーMemoryを勝手に同一視しない。
- **人格や親密さを強制しない。** 個人化した対話は実用性と利用者の好みを尊重する。擬似感情や自律意思、固定された人間的な人格の再現を要求せず、ユーザーがいつでも通常のソフトウェアとして扱える。
- 本決定は製品コンセプトの確定であって、実装済み、定量的な学習効果を実証済み、正式なReleaseスコープへ新規追加、Workstream開始許可を意味しない。0.1／0.2／0.3／0.4以降の既存Gateとロードマップ境界を維持する。

## 2026-11-25 — Nagi Persona（仮称）：状況に応じた学習内容の利用と提案

### CONFIRMED — 製品の方向

- ブラウジングだけでなく、許可された学習・Memoryに基づく提案全体を、ユーザーの現在の状況や目的に応じて使い分ける方向を採用する。Business／Private等は例示であり、仕事の文脈に適した調査・支援と私生活に適した支援を区別し、予期しない個人的情報の露出を避ける。
- 「覚えること」と「現在の対話・提案・出力で利用すること」を区別する。利用者が手動で文脈を切り替えられることに加え、許可された入出力・作業文脈に基づきLLMが適切な文脈を判断し、シームレスに切り替えられる体験を目指す。この構想をNagi Persona（仮称）と呼ぶ。
- 既存のProfile／Memoryの所有範囲、明示指示・保護設定優先、現在のPermission／Policy、Source由来、明示的忘却、外部送信・Taskの別承認を維持する。Persona選択は認証、権限付与、別Profileへのアクセス許可、追加監視、Task実行承認ではない。DEC-005の閲覧記憶の保存除外とSearch／User Memory分離、DEC-113の外部由来Memory候補の本人確認は維持する。画面・音声・提案・出力に関するDEC-008／010／020の既存制約を緩和しない。

### PROVISIONAL — 設計候補（未承認の詳細）

- Businessの下に事務作業／プレゼン／会議等、Privateの下に日常生活／外出等を置く階層的Persona、任意追加／編集、共通Memoryと文脈別Memoryの論理的な適用範囲。階層数・名称・既定値・所属・共有条件は未確定。ユーザーからPersona内をさらに分割する案が提示されている。
- 判定と実効制限を分離する案：LLMは最小限の許可された入力や構造化Eventから候補を推定し、OS側の決定論的なContext／Permission境界が実際に参照・表示・送信できる情報を制御する。低確信、矛盾、未分類、文脈切替時は共通の安全な情報に限定し、必要に応じ確認する。手動固定・解除、Task／Workspace／出力先単位の適用、画面共有／プレゼン時の抑制、既存会話・Context cache・保留通知への反映、学習履歴の可視化は詳細設計候補。
- 閲覧Archiveの明示検索時のみ参照する既定、閲覧由来の提案利用の個別Opt-in等は別途確定する。DEC-005の既存保存方針を本追記だけで変更しない。
- 具体的な記憶の分類、入力信号、分類方式、切替条件・閾値、表示、音声、生成途中の出力制御、データ構造、性能、評価、適用版・時期はPROVISIONAL。0.3 Personal Agentの設計と整合させるが、実装開始・必須Acceptance追加・Release／Activation Gate変更を意味しない。
