# DEC-014 — Workspace状態の自動保存と名前付きチェックポイント

**状態:** CONFIRMED（詳細未確定）  
**最終合意日:** 2026-11-05  
**適用候補:** Nagi OSの将来のWorkspace UX。実装時期は未確定  
**関連:** DEC-002、DEC-003、DEC-004、DEC-005、DEC-009、DEC-010、DEC-012、DEC-013、DEC-020、DEC-022、DEC-026、[DEC-040](DEC-040-builder-app-development-project-retention.md)、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md), [DEC-041](DEC-041-builder-app-uninstall-and-data-deletion.md)

## 目的とユーザー体験

Workspaceの作業環境に後から戻れるよう、復元用状態を普段は自動保存し、重要な節目はユーザーが名前を付けて記録できるようにする。

## 確定した仕様（選択C）

- **自動保存:** NagiはWorkspaceの復元用状態を自動保存する。
- **名前付きチェックポイント:** ユーザーは自分で名前を付けたWorkspaceチェックポイントを作成できる。
- **履歴からの復元:** 保存された履歴に基づき、過去のウィンドウ配置・アプリの状態・資料への参照を、対応する範囲で復元できるようにする。完全には復元できない場合は部分成功・失敗を正しく表示する。
- **Workspace本体は自動削除しない:** 古さ、低利用頻度、履歴の整理を理由にWorkspaceを自動削除しない（DEC-012）。
- **Permission / Privacy:** 保存・検索・復元は現在のUser / Profile / ResourceのPermissionとPrivacy境界に従い、過去の権限を自動的に引き継がない。
- **別の保存対象と区別:** Workspaceの復元用状態は、ファイル本文・過去版のバックアップやWaybackのファイル内容復旧とは別機能である。builder製アプリの開発Projectの長期保存は[DEC-040](DEC-040-builder-app-development-project-retention.md)で別途扱い、Workspace snapshotはそのProjectのソース本文バックアップではない。 アプリ本体のアンインストールとProject／関連データの削除も別操作であり、[DEC-041](DEC-041-builder-app-uninstall-and-data-deletion.md)に従う。
- **Task再実行禁止:** チェックポイントの作成やWorkspaceの復元は、中断中のAI Taskの自動再開・再実行を意味しない。

### 自動保存のタイミングと履歴整理（選択C）

- **イベント連動＋定期補助保存:** NagiはWorkspaceに重要な状態変更が起きた際に復元用状態を自動保存し、一定間隔の補助保存も行う。
- **古い自動履歴の間引き:** 保存容量上限に応じ、古い通常の自動保存履歴を間引いて負荷と容量を抑える。
- **保護対象を区別:** Workspace本体とユーザーが作成した名前付きチェックポイントは、自動的に削除しない。これらを通常の自動履歴の整理対象へ混ぜない。
- **軽量な復元用状態:** 原則として配置・アプリ状態・資料参照など復元に必要な状態情報を扱い、ファイル本文の複製バックアップを当然の保存対象としない。PermissionとPrivacyに従う。
- **数値は未確定:** 具体的な保存間隔・容量上限・保持期間は実装時の測定・検証で決定する。現時点で数値を確定しない。

### チェックポイントからの復元先（選択C）

- **既定では新しいWorkspace:** 過去のチェックポイントは、元のWorkspaceを変更せず、新しいWorkspaceとして復元することを標準とする。
- **元のWorkspaceへの復元も選択可能:** ユーザーは、チェックポイントを元のWorkspaceに戻す方法を明示的に選べる。
- **復元前の状態を自動保護:** 元のWorkspaceへ復元する場合は、上書き・再配置に先立ち、復元前のWorkspace状態を自動的に保護する。保護に失敗した場合、保護できたものと見なして上書きしない。
- **安全境界の継承:** いずれの復元方法も現在のPermission / Privacyと手動配置・固定状態を尊重し、ファイル内容を巻き戻さず、中断中のAI Taskを自動再開・再実行しない。

### 復元前自動保護状態の保持（選択C）

- **Workspaceごとの直近1件を必ず保護:** 元のWorkspaceへ過去チェックポイントを復元する前に自動保護した状態は、Workspaceごとに直近1件を保護対象として保持する。次の復元があっても、直近の復元前状態を失わないようにする。
- **一定期間は複数世代も保護:** 復元前の自動保護履歴を直近1件だけに即時集約せず、一定期間は複数の世代を保護する。
- **古い自動保護履歴の整理:** 保護期間を過ぎた古い自動保護履歴は通常の自動保存履歴と同様に容量管理・間引きの対象にできる。ただしWorkspaceごとの直近1件の保護は維持する。
- **保護対象の除外:** Workspace本体とユーザーが明示的に保存した名前付きチェックポイントは自動削除しない。通常履歴の容量管理や古い自動保護履歴の整理に混ぜない。
- **Permission・Privacy:** 保護状態の保存・一覧・復元・整理も、現在のUser / Profile / ResourceのPermissionとPrivacyに従う。ファイル本文のバックアップやAI Taskの再実行を伴わない。
- **未確定の数値:** 自動保護の複数世代を保持する期間と容量上限、整理条件の具体値はImplementation Specでの測定・検証に委ねる。

### 名前付きチェックポイントと保存履歴の管理（選択C）

- **Workspaceごとの履歴一覧:** NagiはWorkspaceごとに名前付きチェックポイントと通常の自動保存履歴を明確に区別し、時系列で表示する。復元前の自動保護状態についても既存の保護区分を尊重する。
- **履歴検索:** ユーザーは保存履歴を検索して、目的のチェックポイントや復元可能な時点を探せる。
- **復元プレビュー:** 選択候補について、ウィンドウ配置、アプリ状態、資料参照など、現時点で復元可能な範囲をプレビューする。利用不能・部分復元の状態も正確に示す。
- **名称変更:** ユーザーは、自身に操作権限のある名前付きチェックポイントの名称を変更できる。
- **明示的な削除と事前確認:** ユーザーは名前付きチェックポイントを明示的に削除できる。削除前には対象と影響を確認できるようにし、対象を確認してユーザーが削除を選択するまでは削除しない。
- **削除対象の限定:** チェックポイントの削除は指定された当該チェックポイントに限定し、Workspace本体、資料ファイル、他の名前付きチェックポイントや保存履歴を巻き込んで削除しない。ユーザー指定の名前付きチェックポイントおよびWorkspace本体の自動削除は禁止する。
- **PermissionとPrivacy:** 履歴の一覧、検索、プレビュー、改名、削除および復元は、その時点のUser / Profile / ResourceのPermissionとPrivacyを守る。復元プレビューによる未認可情報の漏出やAI Taskの自動再実行を認めない。

### Workspaceとチェックポイントの自然言語横断検索（選択C）

- **横断検索:** 過去Workspaceと、各Workspaceに紐づく名前付きチェックポイント・通常の自動保存履歴・復元前保護履歴を自然言語で横断検索できるようにする。既存のWorkspace意味検索（DEC-012）と保存履歴検索を一貫した体験として扱う。
- **検索できる情報の範囲:** 現在のUser / Profile / ResourceのPermissionとPrivacyで参照が許可されたWorkspace名、チェックポイント名、保存日時、作業文脈、復元用メタデータを検索根拠とする。これを理由にファイル本文を無断で走査・索引化・露出しない。
- **理由付きおすすめと代替候補:** 関連性が最も高いと判断した候補を理由付きでおすすめし、他候補も提示する。検索理由は実際に許可された保存済み情報に基づき、未確認の作業完了・テスト成功などを推測して事実扱いしない。候補を絞れない場合の短い確認はDEC-012に従う。
- **候補ごとのプレビュー:** 各候補に、Workspace名、保存日時、履歴の種類、アプリ・画面配置・資料参照の復元可能性を表示する。復元不能・一部復元可能・不明な項目は正確に区別し、結果やプレビューを復元実施と混同しない。
- **機密情報の非表示:** 検索対象・検索結果・おすすめ理由・プレビューに対し現在のPermissionとPrivacyを適用する。権限外の名前、作業文脈、資料参照、内容を推測可能な形で漏らさない。過去の権限を検索・復元に引き継がない。
- **最終操作はユーザーが選択:** 復元対象のWorkspace／チェックポイントと復元先は、最終的にユーザーが選ぶ。既定は新しいWorkspace、元Workspaceへの復元は明示選択とし、既存の復元前保護を適用する。検索結果を根拠とする自動復元、ファイル内容の巻き戻し、AI Taskの自動再開・再実行はしない。

### Workspace検索用メタデータと重要な節目の要約（選択C）

- **軽量な基本情報:** Workspace検索には名前、保存日時、作業文脈、復元用状態等の必要最小限のメタデータを保持する。
- **短い節目要約:** 重要な作業の節目で、利用が許可された情報から短い作業文脈の要約を自動生成する。
- **根拠と確度:** 情報源・由来を記録し、確認済み事実とAIの推測を区別する。推測だけで成功・完了を確定したと表示しない。
- **ユーザーの管理:** 検索用記録を確認・修正・検索対象から除外・削除できるようにする。Workspaceや名前付きチェックポイントの削除とは分離する。
- **プライバシー:** 機密分類、Owner、Permission、Privacyを守り、ファイル本文や会話全文を無断で収集・索引化しない。情報源の機密属性を要約でも保持する。
- **変更と忘却の反映:** 権限変更、元情報や検索記録の削除・修正・除外、明示的忘却を、派生検索索引・キャッシュ・要約の利用可否へ反映する。忘却した情報を古い履歴から無断再学習しない。元ファイル、Activity、Waybackなどの別管理対象との削除範囲を区別する。
- **長期Memoryと区別:** Workspace履歴・検索用メタデータ・節目要約は長期Memoryとは別管理とし、検索記録を作っただけで長期Memoryに自動昇格させない。DEC-003〜005の既存Memory Policyに従う。
- **未確定:** 保存容量、要約の頻度、索引方式などの具体的な実装条件は測定・検証で決定し、本決定でRelease / Activation Gateを変更しない。

### 非LLMイベント検出と負荷に応じた節目要約（選択C）

- **軽量な検出:** 重要な作業イベントは非LLMの軽量処理で検出し、権限のある基本メタデータを保持する。
- **必要時だけ要約:** 重要な節目、Workspaceの切り替え、名前付きチェックポイント作成などを契機に、必要な場合だけ短い作業要約を生成する。
- **負荷に応じて延期:** 前景操作を優先し、高負荷時は要約だけを安全に延期する。アイドル時など余力がある場合に生成できるようにする。
- **重複と正確性:** 重複要約を統合し、情報源と確認済み事実・AIの推測を区別する。
- **安全境界:** Permission、Privacy、明示的忘却を優先する。LLMで常時監視せず、ファイル本文・会話全文を無断取得しない。延期後も実行時の権限と忘却状態を再確認する。
- **状態保存は継続:** 要約の延期はWorkspace状態の自動保存や基本メタデータの記録を停止しない。LLM不在でも通常のWorkspace管理を利用できる。
- **実装検証:** 節目判定、延期条件、生成頻度、重複統合方式、負荷上限の具体値は未確定で、実装検証時に決める。既存のRelease / Activation Gateは変更しない。

### 延期したWorkspace要約の再起動後引継ぎ（選択C）

- **永続化:** 延期した作業要約の最小限の処理待ちメタデータを保持し、再起動・電源断後も引き継ぐ。本文や会話全文を無断で保存しない。
- **実行前検証:** 再ログイン後などに現在のUser、Profile、Permission、Privacy、Sourceの有効性と明示的忘却を再確認する。安全かつ必要な要約だけを対象とする。
- **前景優先:** 起動直後に無条件で推論せず、前景を妨げない余力のある時に処理する。高負荷時は延期する。
- **整理:** 不要・重複・失効した処理待ちは整理し、実行不能・失敗・未完了を成功と表示しない。
- **分離:** Workspace自動保存と基本メタデータ記録は維持する。中断AI Taskや副作用のあるActionは自動再開・再実行しない。
- **未確定:** 処理待ち容量・保持期限・再試行条件・失敗時の扱いと実装方式は検証で決める。Release / Activation Gateは変更しない。

### 延期要約の通知と手動管理（選択C）

- 通常は安全にバックグラウンド処理し、待機・延期・失敗を一覧で確認可能とする。
- 長期停滞またはユーザー対応が必要な場合のみDEC-008に従って画面通知をまとめて控えめに表示する。
- 個別または確認済みの一括対象について、実行要求・延期・処理待ち破棄をユーザーが選択できる。
- 実行要求では現行User、Profile、Permission、Privacy、Source有効性、明示的忘却、OS資源制限を再評価する。失効・未許可分は実行しない。
- 破棄は処理待ち情報に限り、Workspace・名前付きチェックポイント・既存履歴・元ファイルを削除しない。
- 中断AI Task・副作用Actionは自動再開しない。Workspace状態保存は維持する。
- 通知条件、長期待機閾値、集約方法、UI、容量は実装検証で決定する。既存ゲートを変更しない。

### Workspace復元時の未保存編集の回復と競合（選択C）

- **対応アプリの回復情報を参照:** 対応アプリが正規APIとそのアプリ独自の保存Policyに基づいて保持した未保存編集の回復情報を、Workspace復元時に参照できるようにする。
- **本文バックアップを作らない:** Workspace自体はファイル本文の複製バックアップを作らない。アプリが保持する回復情報の利用は、Workspaceによる本文複製とは区別する。
- **競合を事前にプレビュー:** 現在の文書・編集状態と過去の回復候補に競合がある場合、どの状態をどこまで復元できるかと、確認できる差異を復元前に示す。
- **ユーザーが復元方法を選択:** ユーザーは現状維持、回復候補の利用、または可能な場合に回復候補を別コピーとして開く方法を選べる。
- **無断変更を禁止:** プレビューやチェックポイント選択だけで、現在の文書を上書きしたり本文を過去へ巻き戻したりしない。既存の復元前保護と明示的な復元選択を維持する。
- **実行時の再評価と正確な結果表示:** 復元時に現在のPermission、Privacy、Owner、Resource Revisionを再評価する。未対応アプリや回復不能な状態は、部分復元または復元不能として正確に示す。
- **Task実行と分離:** Workspaceチェックポイントの復元およびアプリ回復情報の利用は、中断中のAI Taskや副作用Actionの再実行を意味しない。
- **実装検証に委ねる事項:** 正規API、回復情報の形式、競合判定、差異の提示方法、対応アプリと別コピーを開く方法の詳細は実装検証で決める。具体値を本決定で追加せず、既存Release / Activation Gateも変更しない。

### 別端末への選択式Workspace移行（選択C）

- **Profile移行と分離:** NAGI ProfileのExport / Importとは別に、ユーザーは移行したいWorkspace・名前付きチェックポイント・作業履歴を選んで別のNAGI端末へ引き継げるようにする。Profile移行だけでWorkspace全体を無条件に移行・同期しない。
- **対象と範囲を事前確認:** 移行前に選択対象と含まれるデータ範囲を確認できるようにし、認可された必要な状態・メタデータを引き継ぐ。移行対象外の履歴や機密情報を黙って同梱しない。
- **ファイル・アプリ等は別管理:** ファイル本文、インストール済みアプリ、端末固有設定の移行は、それぞれ別の明示的な操作・Policyで扱う。Workspace移行はファイル本文の複製バックアップやアプリ移植を意味しない。
- **移行先で現行権限を再評価:** 新端末ではUser / Profile / Owner / Permission / Privacyと参照先Sourceの有効性を再評価する。元端末の権限・認可を移行先へ自動継承せず、利用できない情報は検索・プレビュー等から除外する。
- **部分復元と代替候補:** 参照先や対応アプリが使えない場合、利用できる代替候補、部分復元、復元不能を正確に表示する。代替候補の提示は無断のアプリ導入、資料取得、元データ変更を許可しない。
- **画面環境への適応:** ディスプレイ数・解像度等が異なるときは対応可能な範囲で配置を調整する。ただしユーザーの固定指定と手動配置を尊重し、既存Workspaceやユーザーの配置を無断で上書きしない（DEC-009、DEC-010）。
- **Taskとの分離:** Workspace・チェックポイント・履歴の移行や復元をきっかけに、中断したAI Taskや副作用のあるActionを自動再開・再実行しない。
- **未確定:** クラウド同期の具体方式・提供範囲、移行パッケージ形式、既存Workspaceとの競合解決、容量・具体的な対応範囲・実装時期は別途検証・決定する。本決定だけでRelease / Activation Gateや既存Implementation Specを変更しない。

### 移行先Workspaceとの競合保護と統合選択（選択C）

- **既存Workspaceの保護と既定動作:** 別端末への移行では、移行先にあるWorkspaceを保護し、既定では移行元Workspaceを独立したWorkspaceとして取り込む。同名であることだけを根拠に、移行元と移行先を同一Workspaceと判定しない。
- **差異と統合候補の提示:** 識別情報、由来、保存履歴などを使って安全に比較できる場合は、移行元と移行先の差異および統合候補を示す。安全に比較できない場合は同一性を推測で確定しない。
- **ユーザーによる移行方法の選択:** ユーザーは移行元を別Workspaceとして保持するか、統合する履歴・名前付きチェックポイントを選ぶか、移行を中止するかを選択できる。統合では対象と影響を事前にプレビューし、ユーザーの選択を確認してから適用する。
- **実行時の再評価:** 統合または移行の適用前に、移行先の現在のUser / Profile / Owner / Permission / Privacy / Source有効性 / Revisionを再評価する。以前の許可やプレビュー結果をそのまま適用可否の根拠にしない。
- **既存状態を無断変更しない:** 移行元Workspace、移行先の既存Workspace、既存の名前付きチェックポイント、既存履歴、固定指定および手動配置を、無断で上書きまたは削除しない。
- **不確実・非互換項目の扱い:** 互換性がない項目、Workspaceの識別が不確かな項目、安全に競合解決できない項目は、他の状態へ混ぜず分離して保持するか、未反映として明示する。
- **Task・副作用Actionとの分離:** 移行・統合によって中断中AI Taskや副作用Actionを自動再開・再実行しない。
- **未確定:** 同一性の具体的判定、履歴統合、衝突解決、復旧・ロールバック、容量および対応範囲は実装検証で決める。既存のファイル本文・アプリ・端末固有設定の別Policy、クラウド同期等の未確定事項、およびRelease / Activation Gateは変更しない。

### 別端末Workspace移行の隔離・検証・中断復旧（選択C）

- **隔離して検証後に確定:** 別端末への移行では、移行先の既存Workspace・名前付きチェックポイント・履歴を保護する。可能な範囲でデータを一時的な隔離領域に取り込み、内容・完全性・互換性・移行先の現行権限・Revisionを検証してから確定反映する。
- **途中状態を正確に記録:** 移行途中のエラー、容量不足、再起動、電源断では未確定分を勝手に反映しない。完了済み、未反映、失敗、結果不明を区別して記録・表示する。
- **再開時に現状を再評価:** 移行を再開する前に、現在のUser / Profile / Owner / Permission / Privacy / Source有効性 / 明示的忘却 / Revisionを再検証する。ユーザーが安全な続行、再試行、中止、確認済みの部分移行結果の保持を選べるようにする。
- **再試行の重複・上書き防止:** 再試行で履歴やチェックポイントを重複作成せず、移行先の既存Workspaceを上書きしない。結果が不明な反映は確認可能な状態を照合し、安全性を確かめられない操作を盲目的に再実行しない。
- **復旧結果を正確に表示:** 安全に戻せない確定済み反映をロールバック済みと表示しない。実際に反映された状態と回復可能性を示す。
- **移行元と他機能から分離:** 移行元データを自動削除しない。ファイル本文、アプリ、AI Task、副作用Actionの移行や自動再実行はWorkspace・チェックポイント・作業履歴の移行と分離する。中断AI Task・副作用Actionを自動再開・再実行しない。
- **数値・方式は未確定:** 隔離データの保持・整理、検証方法、移行単位、容量、再試行・復旧条件は実装検証で決める。具体的な数値を本決定で追加せず、既存のRelease / Activation Gateや実装許可を変更しない。

### Workspace移行データの安全なExport / Importと受け渡し（選択C）

- **オフラインファーストの標準方式:** Workspace・チェックポイント・作業履歴の端末間移行は、ユーザーが対象、データ範囲、機密分類を確認したうえで、暗号化された移行パッケージをExport / Importする方式を標準とする。ネットワークやクラウド接続を移行の前提にしない。
- **パッケージの保護:** パッケージには完全性・改ざん検出と、Version・Source・Owner等の必要な由来メタデータを持たせ、内容を適切に秘密保護する。平文の不要な一時複製を避ける。メタデータやパッケージを所持していることだけで、Userの認証、Owner関係、Permission、Import先の認可、Action実行許可を証明したものと扱わない。
- **将来の直接転送:** 将来、ユーザーが双方の端末を確認して行う暗号化直接転送を追加できる構成とする。その場合も、Export / Importと同等の認可、完全性・互換性検証、隔離、既存データ保護を適用する。直接転送を標準方式へ置き換える決定ではない。
- **Import時の現行状態を再評価:** Import時に、移行先の現在のUser / Profile / Owner / Permission / Privacy / Source有効性 / 明示的忘却 / Revisionを確認する。移行元の古い権限、以前のプレビュー、パッケージ内の申告は現在の認可の代わりにならない。
- **未信頼・破損・非互換データ:** 信頼性、完全性、互換性または権限を検証できないデータを無条件に適用しない。安全な隔離と確認に回し、結果を正確に示す。隔離・検証後の適用、中断復旧、結果不明、再試行および部分結果の扱いは、上記「別端末Workspace移行の隔離・検証・中断復旧」の決定にも従う。
- **外部共有と別操作:** パッケージをクラウドへ送信すること、またはクラウド同期することは端末間移行の標準方式に含めず、別の明示的な操作とPolicyで扱う。DEC-002のサービス・情報区分・目的等に基づく外部送信許可を迂回しない。
- **移行対象の境界:** ファイル本文、アプリ、端末固有設定は別の明示的操作・Policyで扱う。移行元データを自動削除せず、AI Taskや副作用Actionを移行対象に含めず、自動再開・再実行しない。
- **Release / Activation Gate:** 本決定は既存のRelease / Activation Gate、Acceptance、実装担当範囲を変更せず、実装開始許可を与えない。

> **2026-11-16 全OS Secrets管理の後続決定:** [DEC-086](DEC-086-nagi-secrets-service-hybrid-key-protection.md)で、OS全体の秘密情報管理をNagi独自Secrets ServiceとTPM／TEE対応機器優先＋非対応機器の暗号化ローカル保管によるハイブリッド方式とするC案をCONFIRMED。本節の**Workspace Exportはユーザー指定パスフレーズが基本**という既存仕様、別保管の復旧キー等、クラウド自動鍵預託なし、復号とImport認可の分離、鍵喪失時の復号不能は変更しない。一般Key Store・TPM連携の採用からExport鍵方式を一律に置換すると推定しない。具体暗号・回復・Key Store APIは未確定。

### Workspace移行パッケージの暗号鍵管理と回復（選択C）

- **オフラインファーストの鍵管理:** 移行パッケージの暗号鍵管理はオフラインファーストとする。ユーザー指定パスフレーズによる移行を基本とし、ユーザーが明示的に別途保管する復旧キー等の安全な回復手段も設計上許容する。
- **Export前の説明:** Export前に、利用可能な回復手段と、パスフレーズ・復旧情報を失った場合に復号できなくなる影響をユーザーへ説明する。復旧情報はユーザーが管理する。
- **秘密情報の保護:** 復号に必要な情報を移行パッケージに無防備な形で同梱しない。クラウドへの鍵預託や外部送信は既定で行わない。秘密情報の無用な一時保存・平文複製を避け、保護された一時情報は適用されるPolicyに従って整理する。
- **将来の直接転送:** 暗号化直接転送では、双方の端末認証と鍵交換を利用できる構成とする。Export / Importと同じく、Import側の現行認可・検証・隔離・既存データ保護を適用する。
- **復号と認可の分離:** 復号に成功したことやパッケージを所持することを、Workspaceへの操作権限、Owner関係、PermissionまたはAction実行許可の証明とみなさない。Import時には現在のUser / Profile / Owner / Permission / Privacy / Source有効性 / 明示的忘却 / Revisionを再評価する。
- **回復不能の正直な表示:** 必要な鍵と復旧情報がすべて失われた場合は復号不能であることを正確に示す。裏口や保証のない自動復旧を設けない。
- **未確定事項:** 暗号アルゴリズム、鍵導出・保管・失効、復旧キー形式、認証UI、一時情報の具体的な保持期間・整理方式は実装検証で決める。既存Release / Activation Gateは変更しない。

### 将来のWorkspace同期（選択C）

- **オフラインファーストと端末独立:** Workspace同期はオフラインファーストとし、既定では各端末のWorkspace・チェックポイント・履歴を端末ごとに独立して管理する。別端末への選択式移行と、同期を既定で有効にすることは区別する。
- **明示的な有効化と範囲選択:** 将来、ユーザーが明示的に同期を有効にする場合、対象Workspace、チェックポイント、履歴、相手端末および共有範囲を選択できる設計とする。選択されていない対象や範囲を同期しない。
- **将来の転送経路:** 端末間の暗号化直接同期と、ユーザーが別途明示的に許可したクラウド同期を将来の選択肢として許容する。どちらも0.3の必須機能ではなく、本節は方式・提供時期・実装を確定しない。
- **暗号化と本人・所有者の認証:** 同期データを暗号化し、対象端末およびUser / Profile / Ownerを認証する。暗号化、端末登録、またはパッケージ所持だけで同期対象への認可を代替しない。
- **同期時の再評価:** 同期の受信・表示・適用の各時点で、現行Permission、Privacy、Source有効性、明示的忘却、Revisionを再評価する。機密分類と外部送信Policyを守り、失効した権限や情報を勝手に復活させない。クラウド経路は明示許可された範囲に限り、DEC-002の外部送信制約を迂回しない。
- **オフライン編集の競合:** 各端末がオフラインで独立更新した場合、差分と競合をユーザーが確認できるようにする。安全に統合できない状態を自動上書き・削除せず、解決されるまで分離保持または未適用として扱う。
- **移行・同期対象の境界:** 元ファイル本文、インストール済みアプリ、端末固有設定はWorkspace同期に含めず、別の明示的操作・Policyで扱う。中断したAI Taskや副作用Actionを同期を契機に自動再開・再実行しない。
- **未確定:** 同期プロトコル、履歴統合、同期先管理、鍵の作成・保管・失効、保持・削除、容量、通知・競合解決UI、提供時期は将来の実装検証で決定する。既存のRelease / Activation Gate、Implementation Spec、Acceptance、実装担当範囲は変更しない。

### ExportパッケージとImport一時データの分離・整理（選択C）

- **保存対象の分離:** ユーザー管理の暗号化Exportパッケージと、Import処理中の隔離・復号・検証用一時データを明確に分けて管理する。
- **パッケージはユーザー管理:** 移行完了後も暗号化パッケージを無断削除しない。保管場所・容量・機密分類と削除候補を示し、ユーザーが保持または削除を選べるようにする。
- **Nagi管理の一時データ:** 移行結果と復旧の要否をユーザーが確認した後、安全な条件で自動整理する。失敗・中断・結果不明の場合は復旧に必要な状態を保護し、必要な確認前に削除しない。
- **削除対象の所有境界:** 外部媒体、他ユーザーのデータ、ユーザーが保存指定したバックアップを自動削除対象にしない。外部媒体やユーザー管理パッケージの削除は、既存の所有権・Permissionに従う。
- **削除結果の表示:** 削除済みの表示は実際の処理結果に基づける。SSD等で完全消去を保証できない場合は、その限界を正確に説明する。
- **未確定の実装値:** パッケージ・一時データの保持期限、容量、削除方式、通知UIは実装検証で決定し、推測で確定しない。

## 後続決定・変更履歴（2026-11-16）

[DEC-065](DEC-065-nagi-handoff-work-continuation.md)でNagi Handoff（仮称）を、PC・タブレット・スマートフォン間で文書・Resource・編集箇所・意味的な作業状態を継続する純正OS機能として採用した。既存Continuity、Homeの `home.continue_from_device`、Device Capability、DEC-014の選択式Workspace移行／同期を最大限再利用し、受信先の画面・能力に応じてUIを再構築する。現行User／Profile／Owner／Permission／Privacy・Source有効性／Revisionを再検証し、実体がなければユーザー許可に基づく取得／転送経路または代替を提示する。無断のファイル・個人データ転送／クラウド同期・競合上書きをせず、中断AI Task／副作用Actionを自動再開・再実行しない。名称・UI・復元範囲・経路・共有方式・クラウド利用・瞬時性・対応版はPROVISIONAL。全アプリ・全状態の完全移行、常時オフライン成立、自動同期は保証しない。単発ファイル転送のNagi Shareとは別の概念である。既存Desktop first、Release／Activation／Acceptance Gate、版割当てを変更せず、実装済みを示さない。 本DECの標準Export／Import、端末ごとの独立管理、競合保護・中断復旧・明示的忘却の再評価を維持する。
