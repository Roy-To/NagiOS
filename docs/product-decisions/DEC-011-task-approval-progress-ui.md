# DEC-011 — NagiのTask承認UIと進捗表示

**状態:** CONFIRMED（承認の基本方針・AI Task開始前のWayback復元可能性表示・builder自動切替＋状態表示＋手動指定C・前景会話優先C・追加指示分類表示C・委任Taskの進捗表示C）／PROVISIONAL（UI細部）  
**最終合意日:** 2026-11-15  
**対象:** NagiのTask実行時の承認・音声連携・進捗表示。実装時期は未確定  
**関連:** DEC-001、DEC-008、DEC-009、DEC-010、[DEC-026](DEC-026-ai-change-verification-and-recovery.md)、DEC-015、DEC-016、DEC-018、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)、[0.4+ロードマップ](roadmaps/Nagi_OS_0.4+_Multi-Agent_Organization_Roadmap.md)

## 目的とユーザー体験

承認のために日常操作を不必要に中断させない一方、対象・操作・影響範囲をユーザーが理解し、安全に変更・拒否・中止できるTask体験を目指す。自然言語や音声による修正と、視覚的な確認UIを組み合わせる。

## 確定した仕様

### ハイブリッド承認UI

- 承認画面は**C：ハイブリッド型**とする。通常はNagiとの会話の中のカード型で操作内容や確認事項を提示する。
- 重要な操作、影響の大きな操作、詳細な確認を要する操作では、独立した確認画面に展開する。
- 音声認識とカードを組み合わせ、ユーザーが声で対象や実施内容を訂正できるようにする。訂正した内容はカードに反映し、何を承認するかを確認可能とする。
- 通常操作で承認が必要な場合、現行のOS Policyと認証・Permissionが許す範囲で**音声による承認**も使えるようにする。
- 既に明確に承認したTaskの目的・対象・権限範囲に含まれる下位Actionには、DEC-001に従って不必要な重複確認を求めない。
- 影響の大きい操作について新たに最終承認が必要な場合、音声認識結果だけで実行せず、画面上の明示的な最終承認を求める。音声で内容を訂正することはできる。
- 重要操作の例として、大量削除、まだ承認されていない外部送信、重要な設定変更を想定する。これらの具体的なリスク分類・境界値は未確定。

### Task進捗の基本原則（既存DEC・Roadmapと整合）

- ユーザーが現在のTaskの作業内容、完了・保留・失敗などの状態を理解でき、必要な場合にPause / Resume / Cancel等の操作へ到達できることを重視する。
- Taskを委任した直後は会話内に進捗カードを表示する。その後はコンパクトなTask表示にまとめ、ユーザーが選択すると進捗詳細を展開する（選択C、2026-11-15）。
- Nagiの作業結果や取消の実際の状態は、Activity / Task Log / Waybackの既存設計に従い、不可逆操作、部分成功、結果不明を完了済み・復元可能と誤表示しない。
- AI Task開始前のWayback復元可能性表示は[DEC-026](DEC-026-ai-change-verification-and-recovery.md)に従う。Task開始前の見通しを実行後の復元成功と混同せず、既存の承認・Permissionを変えない。
- Nagi HomeとNagi Desktopのいずれからも、必要な承認やTask状態に到達できるようにする。
- 0.4のプログラミングRole `builder`は、DEC-015の方式Cにより初期はNagi自身がRole切替で実行する。Nagiが計画と初回承認範囲を提示し、ユーザーが対象Workspace・Resource・Action・権限を確認して承認する。承認範囲内の調査・修正・Build / Test・再修正はDEC-016に従い、差分・検証証拠・部分失敗・残課題をNagiが報告する。コード反映はDEC-018、Git commit / pushはDEC-016の別途明示許可に従う。旧「Jev」という内部名称／別Agentの前提は採用しない。

### `builder` Roleの自動切替・状態表示・手動指定（選択C、2026-11-05 CONFIRMED）

- Nagiはユーザーの依頼からプログラミング作業の必要性を判断し、適切な場合に自分の`builder` Roleへ自動切替する。ユーザーがRoleを知っていることは前提にしない。
- Role切替中は「builderで作業中」などの分かる状態を示し、作業中・確認待ち・完了・失敗のTask進捗を既存のTask UIへ結び付ける。Nagi HomeとDesktopから進捗や停止等に到達できる。
- ユーザーが`builder`を明示的に指定でき、Nagiの通常対話にも戻せる。通常対話への復帰だけでは進行中のTaskを勝手に取消・再起動・完了させず、Taskの操作は別に示す。
- Roleの表示・選択は認可ではない。既存DEC-001／011／015／016／018の承認、現行Permission／Policy、Resourceの適用範囲を維持し、重要操作は別の明示的な最終承認を要求する。
- **PROVISIONAL:** Role表示のデザイン、切替を伝える音声／通知の有無、手動Role指定の具体的UI、Task中の切替・並行性の詳細は後続仕様で決定する。

### 別会話と`builder` Task進行の両立 — 選択C（2026-11-05 CONFIRMED）

ユーザーが`builder`の承認済み開発Task中にNagiと別の会話を始めても、会話を優先しながらTask状態を保持する（[DEC-015](DEC-015-builder-role-review.md)）。前景の会話・UIを妨げない範囲で安全な作業を継続し、資源不足ならQueue／一時待機できる。Task表示では「作業中」「資源待機」「確認待ち」「ユーザーによるPause／Stop」「中断後の復旧待ち」「完了／部分成功／失敗」を実態に応じて区別し、必要な操作へアクセスできるようにする。

**前景会話の開始・復帰はTaskの自動取消や再実行ではない。** 資源待機のみの有効な承認済みTaskは現行Permission／Policy・Scope・Revision・Budget等を再検証したうえで続行できるが、ユーザーが明示停止したTask、承認待ち、クラッシュ／再起動後の復旧待ちTaskは勝手に再開しない（DEC-020／022）。具体的な表示位置・通知頻度・進捗指標はPROVISIONAL。初期に独立Agentや複数LLMの並列稼働を必須にしない。

### 追加指示・別の開発依頼のTask表示 — 選択C（2026-11-05 CONFIRMED）

`builder` Taskの実行中に追加指示を受けた場合、Nagiはユーザーへ、**既存Taskに組み込む変更**、**別件としてQueueした新Task**、**競合／優先順／追加承認の確認待ち**を分かるように示す（DEC-015／016）。別件Taskの登録を自動的なAction実行許可として扱わず、対象Workspace・Resource・Action範囲を明確にして必要な承認を得る。大きな変更や競合がある場合は、何が完了・保留・結果不明なのか、元の作業・成果・差分にどう影響するかを説明し、ユーザーの選択を求める。

追加指示の受付によって従前Taskを無断で消去・中止・完了させない。進行中のTaskが安全のため待機した場合は、資源待機、権限・承認待ち、競合待ち、明示停止、中断復旧待ちを区別する。表示形式、Priority変更操作、Task間の対応付けUIはPROVISIONALであり、DEC-011の既存ハイブリッド承認方式と0.4 Gateを変更しない。

## 例外・禁止・安全境界

- 音声認識の成功だけを本人認証やOS Capabilityの根拠としない。承認の可否は現行の本人確認・Permission / Policyに従う。
- すでに送信先・内容・Scopeと権限を明示した送信について、重大性だけを理由に常に追加承認するものではない（DEC-001）。未承認またはScope外の操作は承認済みとみなさない。
- 表示カードへの同意は、TaskやResourceの範囲外に権限を拡大させない。表示内容とOSの型付きAction検証は分離する。
- 既存のDEC-008が定めた通常時の静かな通知・許可条件付き音声応答と矛盾しないようにする。
- 本決定は0.1 / 0.2 / 0.3 / 0.4+のRelease / Activation Gateを変更せず、実装開始の許可を意味しない。

## 未確定・暫定案

- 必ず独立した最終承認を要求するActionの厳密なRisk taxonomy、対象量・不可逆性・機密性の判定閾値、事前承認の上限とUI。
- 音声承認のセッション認証方式、誤認識時の再確認基準、表示言語とアクセシビリティ。
- 進捗カードとコンパクトなTask表示の具体的な見た目・配置、選択後に開く詳細項目、％が計測できない処理の扱い、Nagi Barからの展開方法、タスク一覧の件数・並び順。
- Pause / Cancelの正確な停止点、Retry、確認待ち時の表示、失敗時の復旧、詳細画面の表示項目。

## Roadmapとの関連

- **0.2:** 型付きPublic Action、Capability / Permission、Notification、Jobs、Activity、UI design systemの汎用基盤。Agent UIの完成は新たな0.2 Release条件としない。
- **0.3:** 単一Nagi Personal Agentの計画・承認・進捗・取消・Activityとの相関に沿う。具体的なAcceptanceは0.3 Implementation Specで判断する。
- **0.4+:** 専門Agentを追加しても承認・進捗はNagiを通じて提示し、OS Policyは各Action実行時に評価する。0.4+のGateは維持する。
