# DEC-010 — Intent-first UIと作業別レイアウト提案

**状態:** CONFIRMED（既存Intent-first／Workspace自動配置と手動保護、PX-01／02の方針、Workspace表示モードのユーザー手動切替）／PROVISIONAL（モード・UI・Scope・適用技術・性能・提供版）  
**最終合意日:** 2026-11-24（Workspace手動表示モード切替の高水準方向を追加）  
**対象:** Nagiの将来のUI/UX方針。実装バージョン・採用時期は本決定では確定しない  
**関連:** DEC-001、DEC-004、DEC-006、DEC-008、DEC-009、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)、[0.4+ロードマップ](roadmaps/Nagi_OS_0.4+_Multi-Agent_Organization_Roadmap.md)

## 目的とユーザー体験

Nagiは、利用者にアプリのメニュー、細かなクリック、ウィンドウ操作を覚えることを強制するのではなく、利用者が示した**目的・意図（Intent）**に応じて、必要な操作候補と理解しやすい画面を提示する。マウス等の正確なポインティング操作を必要とする場面を減らす一方、従来のGUI操作は完全に維持する。

## 確定した仕様

### Intent-first UI

- **Intent-first UI**をNagiの基本的なUI方針に追加する。ユーザーの目的や作業に応じて、Nagiが提示するカード、操作パネル、確認表示などを柔軟に変化させる。
- Nagi Homeのシンプルな基本デザインを保ちつつ、必要な作業UIを提示する。必要がなくなった操作パネル等は閉じられるようにする。
- ファイルの整理、文書編集、調査、メール、設定など、作業の種類に応じて適切な情報や操作候補を表示する構想とする。
- 音声・自然言語による依頼や修正と、視覚的な候補確認・GUI操作を組み合わせる。
- この構想は、個別アプリや既存ウィンドウを廃止するものではなく、ユーザーは従来どおりマウス、タッチパッド、キーボード、GUIを使って作業できる。

### 複数端末を前提としたUI方針（2026-11-15 CONFIRMED）

- PCに加えてタブレット・モバイルへ展開することを、Nagi OSの基本製品目標とする。
- UIはPC向け画面を単純に縮小するのではなく、端末の画面・入力方法・利用状況に応じて情報の見せ方と操作を適応させる。Nagiの基本体験と従来のGUI操作を保つ。
- この製品目標はPC／Desktop firstの実装順序を変更しない（DEC-017）。Nagi OSのモバイル／タブレット提供時期、対応機器、具体的なUI・性能要件、実機対応は未確定であり、サポートや互換性を保証しない。

### 作業に応じた画面レイアウトと新規Workspace自動配置（選択C）

- Nagiは、現在の作業内容・目的に応じた**画面レイアウトの最適化を提案できる**ようにする。例：資料作成では文書と参考資料を並べる。調べ物ではAlbertとNotesを並べる。
- **新規Workspaceの開始時は、Nagiが目的に適したアプリ・ウィンドウの配置を自動で用意する**ことを標準とする（旧選択Bを基本とする選択C）。自動配置は認可された通常のUI操作に限る。
- **作業中の既存Workspaceの配置は、Nagiが勝手に大きく変更しない。** より良い配置が考えられる場合は提案にとどめ、ユーザーが採用した場合に適用する。提案は拒否できる。
- Nagiは、ユーザーが繰り返し採用する配置や手動調整から、Workspace・Task・作業目的に応じた**レイアウトの好み**を学ぶ。その好みは**次に新規作成するWorkspace**の自動配置へ反映する。単発の操作だけで定着した習慣と見なさず、明示的なユーザー指示は学習した推定より優先する（DEC-004）。
- ユーザーが手動で変更した配置を尊重し、その場で自動的に上書きしない。従来の手動ウィンドウ操作や提案を使わない選択も維持する。
- 自動配置後にユーザーが「元の配置に戻して」と求めた場合、復元可能な配置履歴に基づいて戻せるようにする。復元対象がない場合・部分的にしか戻せない場合には、成功したふりをせず状態を示す。具体的な履歴保存と復元方式は未確定。
- Nagi Home / Desktop間の単なる画面切り替えや「前回の続き」によるWorkspace復元は、新規Workspaceの開始とは区別する。既存のWorkspace状態の連続性と復元上の制約はDEC-009に従う。
- 配置の好みの学習は、Action権限やPermissionを拡大せず、ユーザー・Profile等の既存Memory / Privacy境界に従う。

### 複数ディスプレイを活用する新規Workspaceの自動配置（選択B）

- Nagiは**新規Workspaceの開始時に、利用可能な複数のディスプレイを使ってアプリ・ウィンドウを自動配置できる**。配置は作業目的および適用可能な学習済みの好みに基づく。
- ユーザーが**固定したウィンドウは保護**し、新しいWorkspaceのために位置や大きさを勝手に変更しない。
- **既存Workspaceのウィンドウ・配置を保護**する。新規Workspaceの開始を理由に、作業中・保持中の別Workspaceを勝手に組み替えない。
- **ユーザーによる手動配置を尊重**する。手動で選んだウィンドウ位置や使用ディスプレイをAIの推測で上書きせず、従来の手動操作を継続できる。
- 配置の自動化は適切に認可されたUI操作の範囲とし、別Workspaceのデータに対する追加権限やAction権限を生まない。

### ディスプレイ切断・再接続時の可視性と配置復元

- 外部ディスプレイが切断され、その画面にウィンドウが残って表示不能になる場合は、**残っている利用可能なディスプレイへウィンドウを自動退避**し、作業を継続できるようにする。
- 切断されたディスプレイに固定されていたウィンドウも、画面が物理的に利用できない間は可視性維持のため退避できる。利用可能な画面上の固定ウィンドウや既存Workspaceを不要に押しのけない。
- 切断前の配置を復元可能な形で扱い、ディスプレイを再接続した場合には**元の配置へ復元できる**ようにする。
- ただし、切断中にユーザーが手動で変更した配置は優先して尊重し、再接続を理由に**勝手に上書き・再配置しない**。
- ディスプレイの退避・復元だけを理由に、アプリや中断済みAI Taskを再実行したり、OS Permission / Actionの許可範囲を広げたりしない。完全に復元できない場合は部分成功・復元不能を正確に示す。

## PX-02 — ユーザー主導の適応型UI B＋将来の高度な個人適応C（2026-11-17）

### CONFIRMED — B案を基本とする

Nagiの**Intent-first UI**を、作業目的に応じたカード・操作パネル・確認表示の提案と、**ユーザーがそれらを選択・却下・固定・調整できる主導権**を両立する体験として扱う。Nagi Homeのシンプルな対話中心の基本設計を保ちながら、必要なときに理解しやすい作業UIを提示し、利用者が採用しない提案を拒否でき、ユーザーが明示的に固定・調整した表示やWorkspaceはAIの推測より優先される。このBは**高水準の製品方針**であり、固定対象の範囲、各操作の手順・画面表現、表示候補の順序や切替条件までは定めない。

**既存選択とは別軸:** PX-02の「B」は、既に確定した「新規Workspaceは意図に応じて自動配置する選択C」「新規Workspaceで複数ディスプレイを活用する選択B」を置換しない。作業中の既存Workspaceの大幅な自動再配置禁止、固定ウィンドウと手動配置の保護、利用者が採用した場合だけ既存配置を変更する従前の制約を維持する。

### CONFIRMED — 将来C案へ高度化する方向

Bのユーザー主導・予測可能性を維持し、現在の許可されたTask／Project／Workspace文脈、ユーザーの明示的な設定・訂正と許可された習慣・採用履歴に応じて、情報・候補・パネルの組み合わせを**より適切に個人適応**させる長期方向とする。PC／Tablet／Mobileの画面と入力方式に合う表示へ発展する既存の端末適応目標と両立させるが、特定の端末・Versionや推薦・学習アルゴリズムの提供を今回確定しない。明示的な固定・拒否・手動変更をAIの推定で黙って上書きしない。

### 既存CONFIRMEDの維持と安全境界

- 本DECのIntent-first、Workspace新規作成時の目的別自動配置（複数画面の活用を含む）、既存Workspace・固定ウィンドウ・手動配置の保護、外部ディスプレイ切断時の可視画面への退避と再接続後の復元可能性を継承する。切断中の利用者の手動変更を優先し、復元不能・部分成功を正しく示す。
- [DEC-009](DEC-009-nagi-first-home-desktop.md)のHome／Desktop切替、Conversation／Task／Workspace／App状態の保持、AIが利用不能な場合にも従来のGUI・keyboard／mouse操作を利用できる原則を変更しない。通常アクセシビリティ基盤先行と将来AI-nativeの長期方向はDEC-097に従う。
- [DEC-008](DEC-008-proactive-behavior.md)の「控えめに先回りする」標準挙動、通常の静かな画面提案・音声割り込みの禁止、積極性設定と重大警告の別区分を維持する。動的カードや提案の表示は、Action実行、UI変更、既存Workspace再配置、追加情報収集、長期Memory保存やCloud送信の許可ではない。
- すべての実Action・データアクセスは現行のOS Permission／Capability／Policy、Task承認Scope、Memory／PrivacyとProfileの所有境界に従う。AIが不在でも通常OS操作を遮断しない。0.1／0.2／0.3／0.4+のRelease／Activation／Acceptance Gateと実装開始条件を変更しない。

### PX-02の未決事項（PROVISIONAL／OPEN）

- カード・パネルの選択／却下／固定／変更の**詳細UI**、固定の対象・解除・保持Scope、提示場所、表示順序と優先順位、候補数、切替・復元・誤推定の訂正手順。
- ユーザー文脈からの適応条件・タイミング・抑制・学習の判定基準、個人化と明示設定の競合解決の具体的実装、動的UI schema／component／rendering、アプリ連携とアクセシビリティの詳細方式。
- 学習技術・Model／Providerの選定、Resource負荷と性能／遅延の定量値、適用端末・Version／時期・Workstream・Acceptance。既存の許可済みデータ取得・Privacy規則は未決扱いに戻さない。

### PX-01のHome／Desktop体験との整合（2026-11-17）

**CONFIRMED（高水準の方向）:** [DEC-009](DEC-009-nagi-first-home-desktop.md)のPX-01節で、対話中心の統合Home Bを基本とし、将来は現在のProject・Task・利用目的に応じた情報・操作候補の適応Home Cへ発展する方向を追加確認した。本DECのIntent-first UI・作業別パネルと矛盾せず、既存の基本的にシンプルなHome体験を維持する。

**既存CONFIRMEDの維持:** 新規Workspaceの適切に認可された自動配置、既存Workspaceと固定ウィンドウ／複数ディスプレイのユーザー指定・手動配置の保護、利用者の明示選択優先、AI不在時の通常GUI、Permission／Policy、Task停止・復旧の区別を変えない。Homeを適応表示することと、既存Workspaceを自動で大きく組み替えることを同一視しない。

**PROVISIONAL／OPEN:** Homeの詳細レイアウトと適応UI、各導線・カード数・Nagi Bar配置、文脈判定・パネルの実装方式、AI停止時の詳細なUI、対応端末・技術・提供版。PX-01は既存Release／Activation／Acceptance Gateや開発開始の許可ではない。

## Workspace表示モードの手動切替（2026-11-24）

### CONFIRMED — 高水準の採用方向

- ユーザーが**Workspaceの表示モードを手動で切り替えられる**方向を採用する。タイル／フローティング等の異なる表示モードを選択する体験を目指す。モードの完全な一覧や初期値は未確定。
- 既存の新規Workspaceにおける許可済み自動配置と、既存Workspace・固定ウィンドウ・複数画面に関する**ユーザーの手動配置保護**を維持する。ユーザーが明示的に対象Workspaceのモード変更を選択した場合、その指示はAIの配置推定より優先する。
- 通常GUIから手動操作でき、AIを使わない場合も成立する。モード切替は他Workspaceの無断変更、権限拡大、Task自動実行・復旧待ちTask再開の根拠にならない。

### PROVISIONAL — 未確定の詳細

- タイル／フローティング以外のモード候補、標準モード、Workspace／ディスプレイの適用単位、表示モードの記憶と再起動後の復元。
- 切替UI・ショートカット・自然言語操作、切替時の位置／サイズ／固定ウィンドウの扱い、Undo／Wayback、複数画面との相互作用。
- Nagi独自ShellとLinux／OSS描画基盤（[DEC-108](DEC-108-display-gpu-nagi-shell-oss-graphics.md)）での実装方法、受入・性能・担当・提供時期／版。
- Omarchyや他Linux Desktopをそのまま製品基盤に採用する判断ではなく、DEC-043／108、DEC-123のLinux版0.1公開条件および既存Gateを維持する。

## 例外・禁止・安全境界

- AIが提案した表示内容を、許可済みActionや新しいOS権限と同一視しない。データ取得や変更は現行のPermission / Policy、承認済みTaskおよび型付きPublic Action / Service APIの制約に従う（DEC-001）。
- Nagi / Model Runtimeは非特権のままとし、特権経路への直結、非公開ServiceへのShortcut、画面座標クリックによる権限評価の迂回を導入しない。
- AIによって生成・選択した画面の表示が、勝手な送信・削除・設定変更を意味してはならない。
- AIが利用不能な場合も従来のDesktop / GUI操作を維持する。
- この決定は既存の0.1 / 0.2 / 0.3 / 0.4+実装Gate、Activation、受入条件を変更せず、実装開始許可を意味しない。

## 未確定・暫定案

- 動的UIの具体的なコンポーネント、スキーマ、生成方式と実行環境、アクセシビリティ、表示優先順位。
- 作業中Workspaceへのレイアウト提案のタイミング・通知頻度、新規Workspaceの自動配置対象、プレビュー・差分表示、配置履歴の保存方式・保持期間、配置復元の対応範囲と失敗時UI。
- 複数ディスプレイの優先順位、固定ウィンドウの指定・解除UI、ディスプレイの識別方法、切断中の手動変更検知、再接続時の復元タイミング・確認UI、解像度変更時の詳細挙動、対象アプリ・ウィンドウ判定の具体的な契約。
- 端末性能に応じた負荷上限、対応アプリ、実装時期とAcceptance。
- PC、タブレット、モバイルごとの具体的な対応機器、画面・入力条件、UI適応規則、アクセシビリティ。
- UI提案のために参照するContextの具体的な条件と、データ最小化の実装方式。

## Roadmapとの関連

- **0.1 / 0.2:** 従来GUIとShell、UI design system、Context、Workspace、Public Actionなど既存の汎用基盤を維持する。本DECによって新たな0.2 Release Blockerは追加しない。
- **0.3:** Personal Agentが正規のPublic ActionとPermissionを使う将来構想として整理する。具体的なUI実装は別途ゲートとImplementation Specで判断する。
- **0.4+:** 追加Agentが存在する場合もユーザー向けの一貫した窓口はNagiとする。Agent Teamを本決定だけで有効化しない。

## Foundation #28の後続決定（2026-11-16）

[DEC-097](DEC-097-accessibility-foundation-and-ai-native-long-term-direction.md)により、通常a11y基盤の先行整備と、正確なポインティングに依存しないAI-native操作の長期方向と両立する設計を確定した。動的UI・端末別a11yの細部、視線／ジェスチャー／空間入力等の採用・時期は未決定。Permission／Policyと必要なconfirmationを維持する。
