# DEC-060 — 応答速度を優先するIMEとAIを活用した学習

**状態:** CONFIRMED（IME／日本語入力の賢さ、リアルタイム応答優先、許可されたデータによるAI学習、安全境界、AI不可時の通常入力とモデル非依存の継続性を目指す方針、独自変換エンジンの長期目標）／PROVISIONAL（具体方式・性能値・適用版）

**最終合意日:** 2026-11-25

**対象:** NagiのIME／日本語入力の将来製品方針。提供時期・版割当ては未確定。

**関連:** [DEC-002](DEC-002-cloud-ai-data-sharing.md)、[DEC-003](DEC-003-memory-classification.md)、[DEC-004](DEC-004-memory-learning-forgetting.md)、[DEC-013](DEC-013-lightweight-memory-engine-benchmark.md)、[DEC-020](DEC-020-ai-os-interaction-path.md)、[言語設計](../architecture/language-architecture.md)、[ADR-0015](../decisions/0015-language-architecture.md)、[ADR-0054（0.1のかな限定IME）](../decisions/0054-m18-japanese-ime-kana-only.md)、[ロードマップ索引](roadmaps/README.md)

## 目的とユーザーの意図

> IMEも賢くしたいね。スピード重視だからリニアにAIが走る感じにはならないと思うけど、現状よりも学習の精度はAIを活用したい

NagiのIME／日本語入力を、日常の入力速度を保ちながら、利用者に合った入力を支援する方向へ賢くする。AIを利用すること自体ではなく、許可された経験とフィードバックから学習の精度を向上させることを目指す。

## 確定した製品方針（CONFIRMED）

1. **リアルタイムの入力応答を優先する。** キー入力、候補出し、変換確定などのcritical pathでは速度と予測可能な応答を優先し、都度LLM推論を同期・直列に組み込んで待つ構成を標準としない。これはAIの利用全般を禁止するものではなく、入力のたびにLLMの完了を待つ前提を置かないという製品方針である。
2. **学習精度の向上にAIを活用する。** 利用者の好み、語彙、許可された文脈、訂正・採用結果などを、許可された目的・範囲で学習に活かす。AIの推定より利用者の明示的な指定・訂正を優先する。学習精度や変換品質の向上は目標であり、達成済みの性能を主張しない。
3. **学習・補助処理は入力応答と資源状況を尊重する。** 学習更新や補助推論には、適切な非同期・低負荷の経路を候補とする。DEC-013／020の前景操作優先と適応型資源管理に従う。具体的な処理経路、実行契機、タイミングや負荷上限はPROVISIONALである。
4. **使うほど賢くなるPersonal Agent OSへ整合させる。** 会話だけでなく日常の文字入力にも、許可された学習と個人適応を活かす。[DEC-057（成長するPersonal Agent OS、PR #116）](https://github.com/Roy-To/NagiOS/blob/26709db237a49a88f1e74c90589ea8c714361085/docs/product-decisions/DEC-057-growing-personal-agent-os.md)と、0.3改訂ロードマップのProfile／Memory／Learningの方向に整合する。DEC-057は本記録作成時点で[PR #116](https://github.com/Roy-To/NagiOS/pull/116)に保存され、mainには未統合である。
5. **AIが使えなくても通常IMEを維持する。** AIが無効・不在・利用不能でも通常の文字入力を利用できる。個人の学習状態は特定モデルの重みや一時キャッシュだけに依存させず、モデルを交換しても保持が許された学習を継続できる、モデル非依存の状態を目指す。形式・移行方法・IMEとCanonical Memoryの責務分担は未確定である。

## 入力データと安全境界（CONFIRMED）

- **秘密入力を学習しない。** パスワードなどの秘密入力は学習対象にしない。IMEが入力を扱えることは、全入力の収集・保持・学習への包括許可ではない。利用者データの分類・所有範囲、現行Permission／Policyと許可された目的を守る（DEC-003）。
- **明示的な禁止・忘却を優先する。** 「学習しない」「忘れて」などの指定と機密分類に従う。DEC-004に従い、明示的に忘却した情報を旧辞書・履歴・索引・キャッシュ・Wayback等から自動再学習しない。派生データにも忘却・利用停止を反映し、元データやバックアップ、過去の外部送信の管理境界を区別する。
- **派生した学習結果にも保護を引き継ぐ。** 語彙・頻度・要約などに加工しても、元データの機密分類やUser／Profile等の所有範囲を失わせない。学習によって参照・保存・共有・実行権限を増やさない。
- **Cloud送信はDEC-002の許可に従う。** 許可されたProvider、情報クラス、Purpose、Resource、Profile、期間・Task等の範囲と送信時のPermission／Policy確認を維持する。ローカルAIが使えないことを理由に無許可でCloudへ切り替えない。IMEの学習方針自体は新たな外部送信許可ではない。

## 未確定事項・具体設計案（PROVISIONAL）

- 候補辞書の改善、頻度の調整、誤変換訂正、パーソナル辞書などは具体設計の候補であり、採用済み機能一覧ではない。
- Input Method Engine、既存OSS／辞書の利用、辞書ライセンス、かな漢字変換方式、初期対応範囲と追加の対応言語。日本語を改善する方向は確定しているが、本決定から新たな言語サポートや0.1の漢字変換対応を推定しない。
- AI／モデル方式、LLM以外の学習方式、モデルの選択、ローカル／許可済みCloudの役割分担、個人適応の保存形式とモデル切替時の継続方法。
- 許可された入力・文脈・訂正・採用結果を取得する具体契約、秘密入力を識別・除外する仕組み、保持対象と保持期間、忘却・派生物削除の実装。
- 学習のタイミング、非同期更新や補助推論の採否・経路、更新結果の反映方法、誤学習の検知・訂正方法、CPU／GPU／NPU・RAM・電力の予算。
- 候補表示、学習の確認・訂正・禁止・忘却などのUI、学習履歴との連携。入力内容の全記録を前提としない。
- 入力遅延、応答のばらつき、変換・学習精度、資源負荷を測る方法と合格数値、実装担当、開発開始・提供時期、版・Workstream割当て。

## 既存仕様・Roadmapとの関係

- **現行IME:** ADR-0054は0.1 M18のかな限定IME、`CandidateSource`と`KanaCandidates`、漢字変換を後続版へ送る判断を記録している。本決定は将来の製品方針を追加し、同ADRの0.1限定仕様や受入条件を変更しない。新たなエンジンや辞書の採用も確定しない。
- **言語設計:** ADR-0015と共通言語設計に従い、System Language、Region／Locale、Input Language／Keyboard、AI Conversation Languageの独立性を維持する。既存の日本語の第一級サポート方針と、今回の将来IME改善の版未定を区別する。
- **0.3:** [改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)のProfile／Memory／Learning／モデル非依存性と整合するが、IME機能を自動的に0.3の必須成果へ割り当てない。
- **0.4+／0.5–1.0:** [0.4+ロードマップ](roadmaps/Nagi_OS_0.4+_Multi-Agent_Organization_Roadmap.md)と[Master Roadmap](roadmaps/Nagi_OS_0.5-1.0_Master_Roadmap.md)の前景応答性・資源管理・通常操作の維持を継承する。特定のAgent／モデル、並列推論、版・時期を必須化しない。
- 本記録は方針の保存であり、実装開始、機能の実装・検証済み、性能保証、Release／Activation Gateの変更を意味しない。

## 2026-11-25 — Nagi独自変換エンジンの長期目標

**CONFIRMED（製品・研究開発の方向）:** IMEをNagiの独自性を発揮する重点領域とし、入力UI・個人辞書・学習・候補の個人適応だけでなく、変換エンジン自体にもNagi独自開発の範囲を広げることを長期目標とする。適合するOSS・辞書・言語処理の知見を基礎として活用し、独自エンジンを段階的に組み込める方向とする。日本語を独自変換技術の先行検討対象とする。すべての対応言語について独自エンジンを自作する要件にはせず、日本語以外は各言語の成熟したOSSと母語話者による品質評価を活用する案を検討する。[DEC-127](DEC-127-nagi-design-system.md)の将来10言語対応目標、DEC-109の共通Input Service、本DECの応答速度優先・AI非依存の通常入力・許可された学習・モデル非依存性・秘密入力保護・忘却を継承する。独自性のために変換品質・速度・安定性・アクセシビリティを犠牲にしない。

**REVIEW NOTE（現状）:** mainの `user/nagi-ime/src/lib.rs` を確認。かな限定の `CandidateSource`／`KanaCandidates` の差替え点が存在するが、現在のtraitはひらがなの読みから候補文字列を返す小規模な契約であり、文節・候補スコア・学習・多言語compositionを含む本格的な変換エンジンの完成や互換性を証明しない。

**PROVISIONAL（具体設計・段階案）:**

- 既存OSSの変換経路で実用的なかな漢字変換を目指し、独自の辞書・候補順位・学習経路と、Rust製独自変換エンジンの研究を段階的・並行的に検討する。Mozc等を日本語の比較基準・利用候補とし、辞書／コーパスの出所、ライセンス、再配布条件を個別に確認する。特定OSSの採用、既存コードの移植・fork、独自実装方式、データの利用許諾は未確定。
- 変換エンジンを追加・交換できる共通入力契約、文節分割、辞書探索、候補生成・スコアリング、再変換、予測入力、個人辞書、許可されたProfile／Persona別の候補の再順位付け、入力と非同期学習の分離を検討する。異なる文字体系の入力方式を日本語の読み／候補契約へ無理に固定しない。秘密入力を学習させず、許可されない文脈・語彙・候補を他のProfile／Persona等へ漏らさない。外部エンジンへの文脈提供も認可・目的・最小化に従う。
- 日本語以外では、Rime、libhangul、libxkbcommon等を各言語・入力方式に応じた候補とし、言語固有の辞書・変換方式を尊重する。独自の共通学習・入力UIと接続する案を検討するが、個別エンジン・各言語の入力範囲・対応時期・評価方法は未確定。
- 同じ許諾済み評価データ・条件で既存OSSと独自方式の変換正解率、候補順位、訂正頻度、文節品質、入力遅延（分布を含む）、RAM／disk、CPU負荷、LLM共存、クラッシュ／復旧、学習の分離・忘却・再現性を評価する。独自方式が十分な品質を実証してから標準化・切替を判断し、既存の実用的な経路を維持する。具体数値・研究着手・担当・提供版は未確定。既存ADR-0054の0.1限定仕様とRelease／Activation／Acceptance Gate、Workstream owner／path ownershipを変更せず、依存追加・実装開始・実装済みを意味しない。
