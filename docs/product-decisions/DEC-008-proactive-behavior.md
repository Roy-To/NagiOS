# DEC-008 — Nagiの標準的な働きかけと通知

**状態:** CONFIRMED（標準応対・通知、小さな用事への静かな準備と調整可能な個人適応）／PROVISIONAL（具体的な取得・準備・学習・UI・実装版）

**最終合意日:** 2026-11-16

**対象:** Nagiの標準対話・提案挙動。0.3 Personal Agent以降を主対象とし、0.4+にも継承  
**関連:** DEC-001、DEC-006、DEC-007、DEC-009、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)、[0.4+ロードマップ](roadmaps/Nagi_OS_0.4+_Multi-Agent_Organization_Roadmap.md)

## 目的とユーザー体験

Nagiは、ユーザーに役立つ提案を適切な場面で示しながら、作業を妨げない控えめな応対を標準とする。

## 確定した仕様

### 標準的な働きかけ

- Nagiの標準動作は **B：「控えめに先回りするNagi」** とする。明示的な依頼を待つだけでなく、ユーザーに役立つ提案を行う。
- 作業中はユーザーの作業を中断する形で通常の提案を割り込ませないことを基本とし、通常の提案は画面通知または画面上の表示で提示する。通常の提案のために自発的な音声割り込みはしない。
- Nagiの積極性はユーザー設定で変更できる。

### 音声応答

- 音声会話中は、Nagiは自然な音声で応答する。
- ユーザーがTaskで完了時の音声報告を指定した場合、Task完了時に音声で報告できる。
- 以上は音声機能が利用可能な場合の対話方針であり、音声機能の具体的な実装や保存方式は別途定める。

### 重大警告

- 重大警告は画面上で通常の表示を中断して提示できる。
- 音声による重大警告はユーザーが許可した場合に限る。許可が確認できない場合は音声警告を行わない。
- 重大警告は客観的なOSイベントを根拠とし、AIの推測だけで重大と判定しない。
- ハードウェアまたはシステム異常をAIが判断して重大警告を出す機能は、監視の信頼性が確立するまで保留する。

### 権限境界

- 提案の提示だけで、その提案に含まれるActionを実行してはならない。
- 積極性の設定は提案の出し方を調整するものであり、情報へのアクセス許可、Actionの実行権限、外部送信の許可を付与・拡張しない。
- Actionの実行はDEC-001に定めるOS Permission / Capability、Policy、承認済みTaskの境界に従う。
- 本決定は既存のPermission / Policy、実装許可、release gateを変更しない。

## 小さな未処理の用事への静かな準備（2026-11-16追記）

### 合意の範囲（CONFIRMED）

ユーザーの決定原文：『基本はBかな。ただその具合も調整できるといいし、学習データに寄ってユーザに最適化したい』。

ここでのBは「静かに準備して、タイミングを見て声をかける」。こまごました事務処理、心理的に着手しづらいメール連絡、記憶から漏れやすい買い物・一時的な用事への支援を具体化する。既存の「控えめに先回り」「積極性をユーザーが設定できる」を維持し、全アプリ・全機能へ固定一律の準備動作を義務付ける決定とはしない。「声をかける」は控えめな提案を表し、通常提案への自発的な音声割り込みを新たに認めない。

1. **Bを既定とする:** 催促を繰り返すのではなく、許可された範囲で静かに準備し、落ち着いた時や作業の区切りに本人が確認できる控えめな提案を目指す。過剰な割り込みを避ける。区切りや集中状態を検知する具体方式は未決定。
2. **着手負担を下げる準備を重視:** 単なるToDo催促にとどめず、メール草案、連絡に必要な情報の整理、簡単なメモ化、小さな用事の整理などを支援候補とする。準備自体も現在許可された情報・目的・処理範囲に限る。すべてのメール下書きやメモを直ちに自動生成する決定ではない。
3. **ユーザーによる調整:** 積極性、提案のタイミング・頻度を含む働きかけの具合を設定で調整可能にする。具体的な段階・目盛り・設定スコープ・UI・初期頻度は未決定。
4. **許可された履歴による個人適応:** 既存Memory・習慣と、利用・学習が許された提案の採用・修正・無視・拒否等のフィードバックから、望まれる提案内容、タイミング、頻度への適応を目指す。ユーザーの明示設定・訂正・禁止を暗黙の学習より優先する。無反応を同意・実行許可とみなさず、一度の無視から恒久的な好みや拒否理由を断定しない。Nagi自身の繰り返し提案だけで好みを強化しない（[DEC-004](DEC-004-memory-learning-forgetting.md)、[DEC-057](DEC-057-growing-personal-agent-os.md)、[DEC-058](DEC-058-habit-first-learning-and-optional-teach-mode.md)）。
5. **一時的な用事と長期Memoryを区別:** 買い物の一時メモや短い用事は、長期Canonical Memoryとは区別可能な一時的Task／Reminderとして扱うことを考慮する。用事が生じたことだけで恒久的な好み・習慣へ昇格させない。具体的な登録・保存・保持・完了・削除方式は未決定であり、既存[DEC-003](DEC-003-memory-classification.md)〜[DEC-005](DEC-005-files-albert-memory-lifecycle.md)の分類・所有Scope・由来・忘却規則を維持する。
6. **人間の意思を優先:** 「今はいい」「不要」という拒否、明示停止、忘却を尊重する。明示された停止を学習や再通知で覆さず、忘却対象を過去の履歴から黙って再利用しない。ユーザーの感情や着手を避ける理由を推定だけで断定しない。具体的な抑制期間・再表示条件は未決定。

### 準備・提案・実行の境界（CONFIRMED）

- 既に参照・利用が許可されたContextから候補を考えることと、追加情報の閲覧、アプリの下書き保存、メモ／Task／Reminderの登録、外部送信を分ける。閲覧・保存を含む実操作は、それぞれ既存のPermission／Capability／Policy、承認済みScope、必要な本人承認と型付きPublic Action／Service APIに従う（[DEC-001](DEC-001-agent-autonomy-actions.md)、[DEC-011](DEC-011-task-approval-progress-ui.md)、[DEC-020](DEC-020-ai-os-interaction-path.md)）。
- 提案の有用性、積極性設定、学習結果、未処理候補の発見から権限は生じない。潜在的な用事を探すための新しい監視権限、常時画面監視・無差別収集、アプリ・メールへの包括アクセスを認めない。
- 本追記は端末外共有、メール送信、購入の自動化を新規許可しない。既存DEC-001で既に明確に承認された送信等のScope内では重複承認を強制せず、下書きの採用だけを送信承認とは扱わない。Cloud利用・外部送信は[DEC-002](DEC-002-cloud-ai-data-sharing.md)の既存の許可に従う。
- 静かな準備の方針は、未承認Taskの起動やWorkflowの保存・有効化・改訂・Scheduled／Event-triggered実行を許可しない（[DEC-028](DEC-028-deterministic-workflows-from-habits.md)、[DEC-029](DEC-029-scheduled-event-triggered-workflows.md)）。
- [DEC-073](DEC-073-proactive-friction-discovery.md)の潜在的な不便の発見は関連するが、反復操作・UI・手順の改善提案と、今回の小さな用事への着手支援は区別する。[DEC-055](DEC-055-project-folder-cross-app-context.md)のProject所属も閲覧・保存・送信許可の代わりにならない。小さな用事にProject指定を必須とする決定でもない。
- 必要時の重大警告は本DECの既存の別扱いを維持する。通常提案の抑制を重大警告の一律停止へ拡張しない。

### 説明用の適用例（実装済み・個別実行許可ではない）

- **着手しづらい連絡:** 本人が後回しにしている連絡について、許可されたContextで草案と必要情報を準備し、区切りに確認できる形で提案する。宛先・内容・添付を勝手に確定せず、保存・送信は各操作の承認範囲に従う。
- **買い忘れや短い用事:** 本人から伝えられた買い物や一時的な用事を、許可のある範囲で簡単なメモや整理候補にする。長期Memoryへの自動昇格や購入の実行は導かない。

### 具体化を保留する事項（PROVISIONAL／OPEN）

- 正式機能名、積極性の段階・目盛り・UI、個別通知頻度、集中状態／区切りの検知、拒否後の再表示条件。
- Event・アプリ・メール等の具体的データソース、参照・記録・保存条件、Task／ReminderとMemoryの分離方式、保持期間・削除・Source失効の具体契約。
- 学習方式・重みづけ、フィードバックの解釈・評価、効果推定、誤学習の訂正方法。個人適応をLLMの重み更新方式と決めない。
- 実施範囲、下書き等を自動生成できる具体的条件、準備候補とアプリ内保存の接続方式、実装・モデル利用・省電力、対応アプリ、リリース版・Workstream・Gate。

## 未確定・暫定案

- 「作業中」の判定方法、通常の提案を出す頻度・タイミング、画面通知と画面表示の使い分け。
- 積極性設定の具体的な段階、範囲、保存スコープ、UI。
- 提案を作るために参照できる情報の具体的な条件。既存のPrivacy、Permission、Memoryの各決定に従う。
- 重大警告の対象となるOSイベントの分類、画面表示の具体的な形式、音声許可の設定方法・適用範囲。
- ハードウェア／システム監視の信頼性を確立したと判定する証拠・基準。基準が確立するまでは、AIによる異常判断を重大警告に使わない。
- 音声機能が利用できない場合の具体的な表示・フォールバック方法。既存のOS Permission / Privacy条件は別途適用する。

## Roadmapとの関連

- **0.3 Personal Agent:** Nagiの標準的な対話・提案挙動とする。通常の提案は画面を基本とし、音声会話では音声で応答する。ユーザーがTask完了時の音声報告を指定した場合は音声で報告できる。Actionは既存のPublic Action、Permission / Capability評価、必要な承認を通す。
- **重大警告:** 画面表示と音声の条件は本DECに従う。監視信頼性が確立する前に、AIの推測でハードウェア／システム異常を重大警告として扱わない。
- **0.4+:** 専門Agentの進捗や成果物はNagiを通じて提示する。ユーザー向け音声の窓口もNagiとする既存ロードマップ方針に従う。
- 本DECは製品挙動の決定であり、0.2 / 0.3 / 0.4+のActivation、release gate、実装開始を許可・変更するものではない。
