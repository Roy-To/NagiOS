# DEC-008 — Nagiの標準的な働きかけと通知

**状態:** CONFIRMED  
**最終合意日:** 2026-11-17（PX-02との整合を追加。2026-10-29までの合意を維持）  
**対象:** Nagiの標準対話・提案挙動。0.3 Personal Agent以降を主対象とし、0.4+にも継承  
**関連:** DEC-001、DEC-006、DEC-007、DEC-009、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)、[0.4+ロードマップ](roadmaps/Nagi_OS_0.4+_Multi-Agent_Organization_Roadmap.md)

## 目的とユーザー体験

Nagiは、ユーザーに役立つ提案を適切な場面で示しながら、作業を妨げない控えめな応対を標準とする。

## 確定した仕様

### 標準的な働きかけ

- Nagiの標準動作は **B：「控えめに先回りするNagi」** とする。明示的な依頼を待つだけでなく、ユーザーに役立つ提案を行う。
- 作業中はユーザーの作業を中断する形で通常の提案を割り込ませないことを基本とし、通常の提案は画面通知または画面上の表示で提示する。通常の提案のために自発的な音声割り込みはしない。
- Nagiの積極性はユーザー設定で変更できる。

### 音声応答

- 音声会話中は、Nagiは自然な音声で応答する。
- ユーザーがTaskで完了時の音声報告を指定した場合、Task完了時に音声で報告できる。
- 以上は音声機能が利用可能な場合の対話方針であり、音声機能の具体的な実装や保存方式は別途定める。

### 重大警告

- 重大警告は画面上で通常の表示を中断して提示できる。
- 音声による重大警告はユーザーが許可した場合に限る。許可が確認できない場合は音声警告を行わない。
- 重大警告は客観的なOSイベントを根拠とし、AIの推測だけで重大と判定しない。
- ハードウェアまたはシステム異常をAIが判断して重大警告を出す機能は、監視の信頼性が確立するまで保留する。

### 権限境界

- 提案の提示だけで、その提案に含まれるActionを実行してはならない。
- 積極性の設定は提案の出し方を調整するものであり、情報へのアクセス許可、Actionの実行権限、外部送信の許可を付与・拡張しない。
- Actionの実行はDEC-001に定めるOS Permission / Capability、Policy、承認済みTaskの境界に従う。
- 本決定は既存のPermission / Policy、実装許可、release gateを変更しない。

## PX-02のIntent-first UIとの整合（2026-11-17）

[DEC-010](DEC-010-intent-first-adaptive-ui.md)のPX-02節で、**ユーザー主導の適応型UI B**（作業目的に応じて提示されるカード／パネルの選択・却下・固定・調整を扱う高水準体験）と、**将来C**（許可されたTask／Project文脈・設定・採用履歴等を踏まえる高度な個人適応）の方向を追加確定した。

**既存CONFIRMEDを維持:** Nagiは通常の提案を控えめな画面提示として扱い、作業を妨げる自発的な音声割り込みをしない。積極性設定はユーザーが変更できる。重大警告は客観的OS Eventに基づく別区分として維持し、音声警告はユーザーの許可が必要。カード／パネルの表示・個人化・学習や提案採用だけで、新しいAction権限、情報閲覧範囲、Workflow保存・実行権限を得ない。既存Workspaceの固定・手動配置はDEC-010に従って保護する。

**PROVISIONAL／OPEN:** 表示順序・切替条件、カード／パネルの固定・却下・解除の詳細UI、個人適応・学習技術、負荷・性能、提供Version。本追加記録はRelease／Activation／Acceptance GateやWorkstream開始を変更しない。

## 未確定・暫定案

- 「作業中」の判定方法、通常の提案を出す頻度・タイミング、画面通知と画面表示の使い分け。
- 積極性設定の具体的な段階、範囲、保存スコープ、UI。
- 提案を作るために参照できる情報の具体的な条件。既存のPrivacy、Permission、Memoryの各決定に従う。
- 重大警告の対象となるOSイベントの分類、画面表示の具体的な形式、音声許可の設定方法・適用範囲。
- ハードウェア／システム監視の信頼性を確立したと判定する証拠・基準。基準が確立するまでは、AIによる異常判断を重大警告に使わない。
- 音声機能が利用できない場合の具体的な表示・フォールバック方法。既存のOS Permission / Privacy条件は別途適用する。

## Roadmapとの関連

- **0.3 Personal Agent:** Nagiの標準的な対話・提案挙動とする。通常の提案は画面を基本とし、音声会話では音声で応答する。ユーザーがTask完了時の音声報告を指定した場合は音声で報告できる。Actionは既存のPublic Action、Permission / Capability評価、必要な承認を通す。
- **重大警告:** 画面表示と音声の条件は本DECに従う。監視信頼性が確立する前に、AIの推測でハードウェア／システム異常を重大警告として扱わない。
- **0.4+:** 専門Agentの進捗や成果物はNagiを通じて提示する。ユーザー向け音声の窓口もNagiとする既存ロードマップ方針に従う。
- 本DECは製品挙動の決定であり、0.2 / 0.3 / 0.4+のActivation、release gate、実装開始を許可・変更するものではない。
