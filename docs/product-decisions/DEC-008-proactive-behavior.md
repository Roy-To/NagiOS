# DEC-008 — Nagiの標準的な働きかけと通知

**状態:** CONFIRMED（従前の控えめな提案・重大警告・音声／テキスト、PX-02のユーザー主導の適応UIとの整合、PX-04の会話切替B＋将来ハンズフリーC、PX-07の文脈適応提案B＋将来の提案管理C）／PROVISIONAL（各PXの具体的UI・条件・頻度・Voice認証／Wake Word・技術・性能・版）  
**最終合意日:** 2026-10-29（既存方針）  
**PX-02／PX-04／PX-07追加合意日:** 2026-11-17  
**対象:** Nagiの標準対話・提案挙動。0.3 Personal Agent以降を主対象とし、0.4+にも継承  
**関連:** DEC-001、DEC-002、DEC-006、DEC-007、DEC-009、DEC-011、DEC-110、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)、[0.4+ロードマップ](roadmaps/Nagi_OS_0.4+_Multi-Agent_Organization_Roadmap.md)

## 目的とユーザー体験

Nagiは、ユーザーに役立つ提案を適切な場面で示しながら、作業を妨げない控えめな応対を標準とする。

## 確定した仕様

### 標準的な働きかけ

- Nagiの標準動作は **B：「控えめに先回りするNagi」** とする。明示的な依頼を待つだけでなく、ユーザーに役立つ提案を行う。
- 作業中はユーザーの作業を中断する形で通常の提案を割り込ませないことを基本とし、通常の提案は画面通知または画面上の表示で提示する。通常の提案のために自発的な音声割り込みはしない。
- Nagiの積極性はユーザー設定で変更できる。

### 音声応答

- 音声会話中は、Nagiは自然な音声で応答する。
- ユーザーがTaskで完了時の音声報告を指定した場合、Task完了時に音声で報告できる。
- 以上は音声機能が利用可能な場合の対話方針であり、音声機能の具体的な実装や保存方式は別途定める。

### PX-04 — 音声・テキスト対話の統合（2026-11-17）

**CONFIRMED — B＋将来C**

- **基本方針B:** ユーザーの明示操作で複数ターンの音声会話を開始し、同じ対話の中で音声とテキストを自然に切り替えられる。音声認識の誤りは画面で確認・訂正できる。
- **将来の高水準方向C:** ユーザーが明示的に有効化したハンズフリー音声操作へ段階的に拡張する方向を採用する。これは将来方向の合意であり、Wake Wordや常時待受の採用を決めるものではない。
- 音声会話はユーザーが停止でき、音声入力／出力の停止・利用不能時はText/UIへ切り替えてTask状態を保つ。停止やfallbackを理由にTaskを自動取消・再実行しない（DEC-011）。
- 音声入力や認識訂正はAction権限・本人認証にならず、重要操作における画面上の明示的最終承認を置き換えない（DEC-011）。
- マイク利用はOSの現行Permissionに従う。音声／文字起こしのCloud送信には[DEC-002](DEC-002-cloud-ai-data-sharing.md)の別個の許可が必要で、会話開始やマイク許可だけでは送信を許可しない（[DEC-110](DEC-110-audio-system-oss-nagi-service-measured-optimization.md)）。
- 本方針はDEC-008の控えめな働きかけを変えない。ユーザーが開始していない音声会話にNagiが通常の対話・提案で音声割り込みをしない。重大警告の音声は既存どおりユーザーが許可した場合に限る。

**PROVISIONAL（未決）:** Wake Word採用、常時待受、録音音声／文字起こしの保持・削除、詳細UI、音声本人認証、技術・モデル・Provider、提供版・時期、性能数値。

### 重大警告

- 重大警告は画面上で通常の表示を中断して提示できる。
- 音声による重大警告はユーザーが許可した場合に限る。許可が確認できない場合は音声警告を行わない。
- 重大警告は客観的なOSイベントを根拠とし、AIの推測だけで重大と判定しない。
- ハードウェアまたはシステム異常をAIが判断して重大警告を出す機能は、監視の信頼性が確立するまで保留する。

### 権限境界

- 提案の提示だけで、その提案に含まれるActionを実行してはならない。
- 積極性の設定は提案の出し方を調整するものであり、情報へのアクセス許可、Actionの実行権限、外部送信の許可を付与・拡張しない。
- Actionの実行はDEC-001に定めるOS Permission / Capability、Policy、承認済みTaskの境界に従う。
- 本決定は既存のPermission / Policy、実装許可、release gateを変更しない。

## PX-02のIntent-first UIとの整合（2026-11-17）

[DEC-010](DEC-010-intent-first-adaptive-ui.md)のPX-02節で、**ユーザー主導の適応型UI B**（作業目的に応じて提示されるカード／パネルの選択・却下・固定・調整を扱う高水準体験）と、**将来C**（許可されたTask／Project文脈・設定・採用履歴等を踏まえる高度な個人適応）の方向を追加確定した。

**既存CONFIRMEDを維持:** Nagiは通常の提案を控えめな画面提示として扱い、作業を妨げる自発的な音声割り込みをしない。積極性設定はユーザーが変更できる。重大警告は客観的OS Eventに基づく別区分として維持し、音声警告はユーザーの許可が必要。カード／パネルの表示・個人化・学習や提案採用だけで、新しいAction権限、情報閲覧範囲、Workflow保存・実行権限を得ない。既存Workspaceの固定・手動配置はDEC-010に従って保護する。

**PROVISIONAL／OPEN:** 表示順序・切替条件、カード／パネルの固定・却下・解除の詳細UI、個人適応・学習技術、負荷・性能、提供Version。本追加記録はRelease／Activation／Acceptance GateやWorkstream開始を変更しない。

## PX-07 — 文脈に応じた自然な提案B＋将来の高度な提案管理C（2026-11-17）

### CONFIRMED — B案を基本とする

「控えめに先回りするNagi」という本DECの既定の性格を維持したまま、許可された現在のTask／作業文脈、ユーザーの明示設定・好み、既存のMemory／利用傾向等を踏まえ、**ユーザーの作業を妨げにくく、役立つ場面で自然に届く提案体験**を基本とする。提案の内容と提示の適切さを利用者の文脈に合わせるが、集中しているかどうかを特定のセンサーや判定方式で推測すること、常時監視することは確定しない。

ユーザーが提案を採用しない意思や明示設定を示した場合は、その意思を尊重する。提案を見返す、保留する、却下するといった管理体験の方向を含むが、操作UI、抑制・再提示の具体的規則や通知頻度はまだ定めない。**通常提案は画面で控えめに提示し、自発的な音声割り込みを行わない**既存CONFIRMEDを引き継ぐ。

### CONFIRMED — 将来C案へ高度化する方向

許可された情報とユーザーのフィードバックに基づき、複数の改善候補を**整理・比較し、根拠と期待できる効果を分かりやすく提示し、採否や訂正を踏まえて提案の質を高める**高度な提案管理体験へ、長期的に発展させる。これは候補管理・提案品質の方向性であり、重要度の算定式、スコア、固定UI、自動採用、提供時期・Versionの確定ではない。

### 維持する既存のCONFIRMEDと例外

- 本DECの「控えめな先回りB」、ユーザーが積極性を設定できること、通常の静かな画面提示を維持する。重大警告は別の区分とし、客観的なOSイベントを根拠にした画面割り込みを既定どおり認める。音声による重大警告は明示許可に限り、AIの推測だけを重大警告の根拠にしない。
- [DEC-073](DEC-073-proactive-friction-discovery.md)の「本人がまだ言語化していない不便を、許可された利用傾向から発見し根拠付きで改善案を示す」方針を維持する。推測は事実として断定せず、別解釈・却下・訂正の余地を残す。
- 提案の整理・採用・学習・積極性設定は、Action実行権限、Workflow保存／有効化／正式改訂、UI変更、アプリ開発／導入・公開、外部送信の許可を意味しない。各段階では既存の明示承認、現行Permission／Capability／Policy、Task Scope、Memory／Privacyの境界を守る。許可されていない常時の操作記録・監視・Telemetry収集・Cloud共有は認めない。
- 既存の0.2／0.3／0.4+のRelease／Activation／Acceptance GateやWorkstream開始、機能実装の完了状態を変更しない。

### PROVISIONAL／OPEN — 詳細は未決定

- 提案する頻度・タイミング、作業中の抑制条件・判定方法、通知／画面表示の使い分け、提案を見返す／保留／却下／再提示する具体的な規則や設定。
- 複数候補の整理・比較・優先順位、重要度・確信度・便益の判定基準と評価方法、提案品質へのFeedback反映方式。客観的な安全警告と通常提案の詳細な分類・UI。
- 対象情報・Contextの取得方法、観察／学習の技術、具体的な画面デザイン、性能・対応端末、実装担当・提供Version・時期。既存の権限・Privacy制約を緩めない。

## 未確定・暫定案

- 「作業中」の判定方法、通常の提案を出す頻度・タイミング、画面通知と画面表示の使い分け。
- 積極性設定の具体的な段階、範囲、保存スコープ、UI。
- 提案を作るために参照できる情報の具体的な条件。既存のPrivacy、Permission、Memoryの各決定に従う。
- 重大警告の対象となるOSイベントの分類、画面表示の具体的な形式、音声許可の設定方法・適用範囲。
- ハードウェア／システム監視の信頼性を確立したと判定する証拠・基準。基準が確立するまでは、AIによる異常判断を重大警告に使わない。
- 音声機能が利用できない場合のText/UI fallbackの具体的な表示・切替方法。Text/UIへ切り替えてTask状態を保つ方向はPX-04でCONFIRMED、詳細UXはPROVISIONAL。既存のOS Permission / Privacy条件は別途適用する。
- PX-04の詳細として、Wake Word採用・常時待受、録音音声／文字起こしの保持・削除、詳細UI、音声本人認証、技術・モデル・Provider、提供版・時期、性能数値はPROVISIONAL。

## Roadmapとの関連

- **0.3 Personal Agent:** Nagiの標準的な対話・提案挙動とする。通常の提案は画面を基本とし、音声会話では音声で応答する。ユーザーがTask完了時の音声報告を指定した場合は音声で報告できる。Actionは既存のPublic Action、Permission / Capability評価、必要な承認を通す。
- **重大警告:** 画面表示と音声の条件は本DECに従う。監視信頼性が確立する前に、AIの推測でハードウェア／システム異常を重大警告として扱わない。
- **0.4+:** 専門Agentの進捗や成果物はNagiを通じて提示する。ユーザー向け音声の窓口もNagiとする既存ロードマップ方針に従う。
- 本DECは製品挙動の決定であり、0.2 / 0.3 / 0.4+のActivation、release gate、実装開始を許可・変更するものではない。
