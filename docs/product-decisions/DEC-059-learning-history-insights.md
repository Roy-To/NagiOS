# DEC-059 — 学習履歴の分かりやすい可視化（Nagi Insights・仮称）

**状態:** CONFIRMED（学習した内容・経緯・支援への反映をユーザーが分かりやすく確認できる体験、既存Memoryの訂正・削除と整合すること）／PROVISIONAL（名称・画面・時系列の粒度・具体Schema・評価指標・提供時期）  
**決定日:** 2026-11-16  
**対象:** Nagi Personal Agent OSの学習・Memory管理・ユーザーへの説明体験。実装完了やRelease／Activationの変更を意味しない。  
**関連:** [DEC-003（Memoryの分類・所有・可視化）](DEC-003-memory-classification.md)、[DEC-004（Memoryの学習・忘却）](DEC-004-memory-learning-forgetting.md)、[DEC-005（SourceとMemory）](DEC-005-files-albert-memory-lifecycle.md)、[DEC-008（控えめな働きかけ）](DEC-008-proactive-behavior.md)、[DEC-013（Memory Engine）](DEC-013-lightweight-memory-engine-benchmark.md)、[DEC-014（Workspace履歴）](DEC-014-workspace-state-checkpoints.md)、[DEC-028（習慣とWorkflow）](DEC-028-deterministic-workflows-from-habits.md)、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)。[成長するPersonal Agent OSの製品方針（PR #116）](https://github.com/Roy-To/NagiOS/pull/116)、[習慣学習を主軸とする方針（PR #117）](https://github.com/Roy-To/NagiOS/pull/117)とも整合する（これらのPRのmain反映は独立に確認する）。

## 背景・目的

Nagiは日常の利用から好み・習慣・作業文脈を学び、実用的なPersonal Agentへ成長することを目指す。ユーザーがその過程を理解・検証できるよう、**学習の履歴を分かりやすく閲覧できる機能**を設ける。

既存DEC-003がCONFIRMEDとするMemoryの内容・分類・根拠・最終利用・共有履歴の可視化と、確認・訂正・削除の権利を土台にする。単なるMemoryの保存一覧や全操作の生ログではなく、**「何を学んだか」「なぜそう理解したか」「その結果、どのような支援に活かすのか／活かしたか」**をユーザーが把握できる説明を目指す。

## 確定した製品方向（CONFIRMED）

1. **学習の経緯を見られる:** ユーザーが望むときに、現在保持・参照が許されたMemory／Habit／Preference等について、Nagiが学習・更新した内容と、その経緯を理解しやすい形で閲覧できる。変更が確認できる場合は、いつ頃どう変化したか、訂正・保護・忘却などの状態を区別する。記録が欠ける項目は推測で補完せず、「不明」「記録なし」等と明示する。
2. **根拠が分かる:** 学習内容と、利用可能かつ権限を持つSource／Task／Workspace／採用された提案／ユーザーの訂正など、結び付けられる根拠を示す。確定情報・Nagiによる推定・未検証の解釈を区別する。ユーザーの実際の採用・確認がない推定を、確定した習慣として表示しない。
3. **支援への反映を説明する:** 学習内容が今後の説明方法、作業手順、推奨、Context選択等にどのような影響を与える見込みか、また既に影響したことを検証できた場合には何が変わったかを、可能な範囲で確認できる。効果が未測定の場合は「時間を節約した」「正確になった」等を実績として断定しない。学習履歴の記録自体は行動の自動実行を承認しない。
4. **ユーザーが修正できる:** 学習内容の誤り・好みの不一致をユーザーが確認・訂正・保護指定・利用停止・削除／忘却できる既存DEC-003／004の権利と、一貫した入口を持つ。ユーザーの明示的な訂正は推定より優先する。訂正前の推定を無条件に有効なPreferenceへ戻さない。
5. **普段は静かに学ぶ:** 利用者が毎回学習履歴を開いたり、教示したりすることを成長の条件にしない。確認は必要時に行えることを基本とし、通常作業を妨げない控えめな提案・通知（DEC-008）を維持する。履歴表示を目的に新たな全画面録画・全操作監視・無制限なログ保持を導入しない。
6. **アクセス権と忘却を守る:** 個人・機密・他Profile／Task等の情報の分類・Owner／Scope、現在のPermission／Policy、元資料の現存と利用許可を尊重し、現在参照できない内容は履歴からも露出させない。明示的に忘却した情報を「学習履歴」という名目で再表示・再利用・再学習させない。削除・保持期間はDEC-003〜005を継承する。
7. **異なる履歴を混同しない:** 学習履歴はMemory／Preference／Habitの内容・変化を説明する体験であり、Activity Ledger（操作・Action）、Workspaceの復元履歴、Wayback、ファイル版履歴の代替ではない。それぞれの保存・削除・権限と復元限界を保つ。

## PX-09との整合（2026-11-17）

PX-09ではB案「自然忘却＋ユーザー管理」を基本方針として採用し、将来C案の高度な重複統合・矛盾検出を追加する方向もCONFIRMEDとした。[DEC-004](DEC-004-memory-learning-forgetting.md)がこのMemory lifecycle方針の正本である。本DECの学習履歴体験は、Memoryを必要なときに確認・訂正・保護・忘却できる既存のユーザー管理権と整合する。

自然忘却・Archive・明示的忘却・ユーザー訂正は混同しない。学習履歴を理由に忘却済み情報を再表示・再利用・再学習せず、Source削除、現行Permission、Profile／所有Scopeも既存ルールに従う。将来Cの検出・統合結果をどう履歴化し、提示・適用するかは未決定であり、Cの方式・提供版・時期を確約しない。既存のRetention方針やRelease／Activation／Acceptance Gateも変更しない。

## UX例（方向性の例であり、UI確定・実装済みではない）

- 「最近、何を覚えた？」に対し、保持中で参照可能な学習候補を分かりやすく示す。
- 「月次報告資料は結論を先に置く構成が好まれそうです」という学習候補に対し、採用済み・推定中の区別と、参照可能な根拠・今後の提案への影響を示す。
- ユーザーが「今回は例外だよ」「それは違う」「もう覚えておかなくていい」と修正でき、以降の学習・提案へ既存ルールの範囲で反映できる。

## 既存ルールとの関係・非目標

- DEC-003の**可視化・訂正・削除**を体験として発展させ、DEC-004の**自動記憶・自然忘却・ユーザー指定優先**を維持する。学習を見せるためにMemoryを永続保存・再学習する追加の権限を作らない。
- 根拠となったSourceが削除・ゴミ箱移動・権限失効した場合は、DEC-005に従い依存Memoryと履歴表示の可用性を再評価する。要約やActivity・Waybackから削除済みの情報を復活させない。削除要求への応答ではMemoryと元ファイル・バックアップ等の異なる管理境界を正確に説明する。
- Memory／Preferenceの修正は、Workflowの保存・改訂・実行承認や外部送信の許可とは別。DEC-028等で既に定める承認・Action・Policy境界を変えない。
- 0.3で目指すPersonal Agent／Learningを利用者が理解するための製品方向であり、本決定だけで0.3／1.0等の新しい必須Acceptance、Activation、性能保証を課さない。

## 未確定事項（PROVISIONAL）

- 「Nagi Insights」の正式名称、画面の配置、タイムライン／カード／検索／Project別表示の採用、説明の文章量と表示頻度、学習の変化を示す粒度。
- 学習イベント・Revision・推定／確認状態のデータモデル、SourceからのProvenance・権限再評価・表示時の検証方式、履歴同士の関連付けと保持期間。
- 成長の可視化指標、定量スコア、前後比較や効果検証の条件。根拠がない数値・節約時間・上達度を表示する仕様にはしない。
- 定期的な学習レポートや通知の有無・配信間隔、操作方法、説明生成に用いるAIの要否／負荷・プライバシー条件。
- PX-09のMemory確認・訂正・保護・忘却UI、履歴への反映粒度と保持期間。
- 将来Cの重複統合・矛盾検出アルゴリズム、適用／提案の条件、履歴・Provenanceとの連携。
- 初期対応アプリ、実装担当・時期・対象Version・テスト／Acceptance。
