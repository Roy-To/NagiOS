# DEC-001 — AIの自律性とAction実行

**状態:** CONFIRMED（既存のAI自律実行・権限原則およびPX-05のB＋将来C高水準方針）／PROVISIONAL（リスク閾値・未判定時の具体条件・承認UI・技術・適用版）  
**最終合意:** 2026-11-25（PC内外の作用境界を追加）／2026-11-17（PX-05追加。2026-10-25までの既存決定を維持）  
**対象:** 0.3 Personal Agent、0.4+への継承  
**関連:** DEC-002、DEC-005、DEC-007、DEC-016、DEC-018

## 決定事項

1. **承認済みTask内での自律性:** ユーザーが明確に指定した目的・対象・権限範囲の内側では、Nagiは可逆な下位作業を毎回確認せずに実行できる。必要なPublic ActionとProvider側の権限確認は省略しない。
2. **権限と習慣の分離:** 繰り返された行動やPreferencesから操作方法を学んでも、読み取り・変更・共有・送信の許可範囲が拡大することはない。
3. **メール送信:** 「送信して」という明示の依頼、送信先、内容、対象範囲、送信権限が確定している場合は、毎回の重複確認なしで送信してよい。宛先・CC/BCC・添付・共有先を推測で拡張しない。
4. **機密情報の外部送信:** 機密という理由だけで無条件に再承認を要求しない。ただし、送信先・範囲の明示的な許可、元データの扱い、組織Policyのすべてが送信を認めている必要がある。読める権限は送信する権限を意味しない。
5. **認証情報:** パスワード、秘密鍵、API keyなどは一般的な外部送信や通常のMemory利用と別の厳しい境界で取り扱う。
6. **取消とActivity:** Nagiが何をしたか、どこまで完了したかを追跡し、可能な範囲でPause / Cancel / Undoできるようにする。送信済みメールやRemote変更を「Undo可能」と偽らない。

## PX-05 — 自律実行と承認体験のB案＋将来C案（2026-11-17／CONFIRMED）

**B案を基本とする（CONFIRMED）:** 承認体験は、Actionの種類だけで機械的に固定せず、対象・影響範囲、可逆性、検証可能性、現在のPermission／Policy、事前承認済みTaskの目的・Action／Resource Scope等に応じて段階的に扱う。既存の承認範囲内で安全に実行できる下位Actionには無用な重複確認を求めず、別途の最終承認が必要な重要操作では既存のハイブリッド承認UIと画面上の明示的な最終承認（DEC-011）を維持する。

**将来C案へ高度化する方向（CONFIRMED）:** B案の承認・Permissionの安全境界を維持したまま、許可されたTask文脈、対象データ、利用者の明示設定、実際の検証状態等に合わせて、確認内容の詳しさや提示タイミングをより適切に調整できる体験を長期的な製品方向とする。Cは将来の方向性であり、現時点での機能提供・自動判定方式・特定Versionを採用したことを意味しない。

**適用範囲と禁止（既存CONFIRMEDを維持）:**
- 判定・提示の高度化は、OS／Providerが現行のPermission／Capability／Policyと承認済みScopeをActionごとに検証する義務を変更しない。AIの推測・習慣・個人化・Risk評価だけで権限を付与、拡張、失効解除したり、必要な明示承認を省略したりしない。
- DEC-001の送信先・内容・許可範囲が明確なメール送信の重複承認不要、機密外部送信の別権限とPolicy、認証情報の厳格境界、Pause／Cancel、不可逆作用の正直な説明は引き続き有効。
- DEC-026の**選択A（変更の検証・実在する復元可能性を優先）**は別の判断軸であり、PX-05のB／将来Cで置換しない。DEC-053のTask開始前のWayback復元可能性説明と、DEC-016／018の`builder`用のより厳格な確認・反映・別途Git権限も維持する。

### PX-05の未決事項（PROVISIONAL／OPEN）

- Action／影響範囲／可逆性／検証状態ごとの厳密なRisk taxonomy、重み・数値閾値、例外、承認済みScopeの再評価を画面へ反映する具体条件。
- 未判定・証拠不足・競合・失敗・一部実行等の際に、どの条件で確認待ち／保留／停止／回復へ振り分けるか、その詳細な状態遷移・再判定・操作導線。既存の無許可実行禁止と結果不明を成功としない原則は変えない。
- カード／独立確認画面の具体UI、承認理由・危険性・復元見通しの提示粒度、利用者向け設定、C案の状況適応の判定方法と評価指標。
- 実装技術・Provider契約・対象アプリ・性能、実装順序・提供バージョン・Acceptance。既存Release／Activation／Implementation Spec Gateは変更しない。

## 実行上の優先順位

OSの現在のPermission / Policy > ユーザーの明示的な指示・禁止 > 限定された承認済みTask > 学習した嗜好・習慣。Policyに反するユーザー指示は実行しない。Action実行時に現行Scopeを評価する。

## まだ決めていないこと

- Action種別ごとのリスク分類、事前承認のUI、確認を再要求する重大変更の閾値。
- Task実行の具体的な時間・Retry・Resource上限。
- 可逆Action / 結果不明な外部Actionの厳密な形式とテスト。

## Roadmapとの関係

0.2では型付きPublic Action、Identity、Permission、Activity、Wayback等の土台を整える。0.3で単一Nagiが複数アプリを順次操作する。0.4+の専門Agentは親から**権限を狭める委譲**しか受けられず、独自の権限発行はしない。JevのB実行範囲と成果の完了判定はDEC-016、隔離編集と条件付き反映はDEC-018に定める。

## 2026-11-25 — PX-05 リスク別自律実行とPC内外の作用境界

**CONFIRMED（ユーザー合意）:** リスク別自律実行（5段階を基本とする方向）、ユーザーごとの自律性調整、承認範囲内での連続自律実行を基本とし、PC内部の作業とPC外部に作用する作業を明確に切り分けて管理する。メール送信やCloudへのアップロード等の外部作用はWaybackの復元対象外とする。PC内の操作でも実際に対応するCheckpoint／Provider等が存在する場合のみ復元可能と扱う。Taskに内外両方の作用が含まれる場合、内部変更の復元を外部作用の取消と同一視しない。

**既存の確定境界を維持:** DEC-001の明確に承認済みのメール送信・DEC-002の事前許可範囲内のCloud送信に不要な重複確認を要求しない。一方、内部作業の許可を外部送信・共有・遠隔変更の許可に流用しない。DEC-011の重要操作の画面最終承認、DEC-026／053の実際の復元可能性の事前提示、現行Permission／Policy、外部送信の宛先・目的・機密分類、不可逆作用と結果不明を正直に表示する原則を維持する。承認や習慣学習・自律性設定で権限は拡大しない。外部サービスの取消・削除等は対応Providerで検証可能な別Actionとして扱い、完全復元を保証しない。

**PROVISIONAL（詳細設計案）:** リスクL0〜L4（読取、軽微な可逆変更、外部影響／重要変更、重大／復元困難、禁止または人間専用）、作用範囲Local Read／Local Write／External Read／External Write／Mixedを独立軸とする分類案。外部問い合わせ、同期フォルダへの書込等の間接的外部作用も評価対象とする案。Activityでの内外作用の識別・外部操作フィルター、宛先・結果・復元可否の表示、結果不明の外部操作の重複防止、慎重／標準／積極的／カスタム等の設定名・範囲、閾値・Schema・UI・実装・適用版・Acceptanceは未確定。既存Release／Activation／Implementation Spec Gateは変更しない。
