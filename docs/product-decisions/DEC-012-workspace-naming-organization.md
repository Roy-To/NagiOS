# DEC-012 — Workspaceの自動命名とスマート整理

**状態:** CONFIRMED（細部は未確定）  
**最終合意日:** 2026-11-04  
**適用候補:** Nagi OSの将来のWorkspace UI/UX（実装バージョンとActivation時期は別途決定）  
**関連:** DEC-003、DEC-004、DEC-006、DEC-008、DEC-009、DEC-010、DEC-014、[0.3改訂ロードマップ](roadmaps/Nagi_OS_0.3_Architecture_Roadmap_Revised.md)

## 目的とユーザー体験

Nagiが作業の目的に即したWorkspace名を付け、一覧を分かりやすく整理することで、ユーザーが番号や名前を覚えずとも必要な作業へ戻りやすい環境を目指す。管理の主導権はユーザーに残す。

## 確定した仕様

- **自動命名:** NagiはWorkspaceの作業目的・利用文脈に基づき、内容が分かりやすい名前を自動で付ける。ユーザー自身が名前を付けたり変更したりできる。
- **スマート整理:** Workspace一覧を「固定した作業」「最近の作業」「過去の作業」の3区分に整理する。固定指定のWorkspaceは固定枠に表示し、それ以外を利用状況に応じて最近／過去に整理する。
- **ユーザーの名前を優先:** ユーザーが手動で指定・変更したWorkspace名は、Nagiの自動命名や推定によって勝手に上書きしない。
- **ユーザーの並び順を優先:** ユーザーがWorkspace一覧の並び順を指定・調整した場合、AIによる標準の並び替えよりも優先する。
- **自動削除しない:** Nagiは、Workspaceが古い、利用頻度が低い、あるいは「過去の作業」に分類されたという理由だけで、Workspaceを自動削除しない。
- **分類とデータ操作の区別:** 「過去の作業」は一覧の分類を意味し、Workspace本体、開いていたアプリ、ファイル、履歴、Taskを削除・移動・終了する命令ではない。
- **既存の状態保持を継承:** Workspaceの選択・表示・並び替えだけで、AI Taskを自動再実行したり、保存済みの配置やユーザーの固定指定を勝手に破棄したりしない（DEC-009、DEC-010）。

### 過去Workspaceの自然言語検索と復元（選択C）

- Nagiは自然言語から過去のWorkspaceを意味検索する。
- 検索結果では候補と、アプリ・資料・画面配置の復元可能な状態を提示する。
- ユーザーが選んだWorkspaceについて、アプリ・資料・画面配置を可能な範囲で復元する。復元できない部分は明示する。
- 検索・候補表示・復元は現在のPermissionとPrivacy境界に従う。過去にアクセスできたことだけで権限を得ない。
- Workspaceを復元しても、中断したAI Taskは勝手に再開・再実行しない。

### 複数候補のおすすめと確認（選択C）

- Nagiは過去Workspaceの検索で、最も関連性が高いと判断した候補を**理由付きでおすすめ**し、**他の候補も表示**する。
- 候補を十分に絞り込めない場合に限り、短い確認質問をする。不要な質問は挟まない。
- **最終的に選ぶのはユーザー**であり、Nagiはおすすめや確認質問のみを根拠に勝手にWorkspaceを復元しない。
- 理由・候補・質問には現在の**PermissionとPrivacy**を厳守する。検索だけでAI Taskを再開しない。

### Workspaceとチェックポイントの横断検索（選択C／DEC-014）

- 過去Workspaceだけでなく、各Workspaceの名前付きチェックポイント・自動保存履歴・復元前保護履歴を自然言語で横断検索できる（具体的な保存履歴の仕様はDEC-014）。
- 検索はPermission / Privacyで参照を認められた名前・日時・作業文脈・復元用メタデータに限定する。ファイル本文の無断検索・露出を許可しない。
- 理由付きおすすめと他の候補を示し、各候補のWorkspace名・保存日時・履歴種別・アプリ・画面配置・資料参照の復元可能性をプレビューする。権限外の情報は伏せ、部分復元・復元不能を正確に表示する。
- 最終的な復元対象と復元先はユーザーが選ぶ。新Workspaceへの復元を既定とし、元Workspaceへ戻すときは復元前状態を保護する（DEC-014）。検索だけでWorkspaceを自動復元せず、ファイル内容を巻き戻さず、AI Taskを自動再実行しない。

## 例外・禁止・安全境界

- Workspaceの名前・分類を生成する際に扱う情報は、User / Profile / Task等の既存Owner・Permission・Privacy境界に従う（DEC-003、DEC-004）。表示名の生成を機に利用権限を拡張しない。
- **Workspaceの自動削除禁止は、DEC-004で別途規定する低重要度Memoryの自然忘却を禁止するものではない。** Workspaceそのものと、Memory内の嗜好・要約・履歴は別の管理対象であり、互いの削除ポリシーを無言で流用しない。
- Workspaceの自動命名・整理は、アプリのファイル操作や未承認Actionを実行する権限にならない。
- AIが利用できない場合も従来のWorkspace選択・管理UIを利用できるようにする。新仕様は0.1/0.2/0.3/0.4+の実装Gate、Activation条件、受入基準を変更しない。

## 未確定・暫定案

- 自動命名に利用する情報・生成タイミング・名前の長さ・曖昧な作業目的への対応と編集UI。
- 「最近の作業」と「過去の作業」を分ける期間・利用状況の判断、並び順の初期値、固定指定・解除操作、各区分間の手動移動の具体的な仕様。
- Nagi Home / Nagi Bar / Desktopのどこに一覧を配置するか、一覧の見た目、表示件数、検索・フィルター操作、意味検索の情報源・順位付け・自然言語の解釈方式・候補表示方式。
- Workspace保存・表示・再開とUser / Profile切替、複数端末、アプリ状態復元に関する細部およびAcceptance。
- 自動命名が扱う機密Contextの最小化、ロック中・共有画面での表示抑制などの具体的なUI方式。

## Roadmapとの関連

- **0.1 / 0.2:** 既存のWorkspace、Identity、Settings、Context、UIおよびState保持のPlatform基盤を維持する。本DECで新しいRelease blockerを追加しない。
- **0.3:** Personal AgentのProfile、Memory、Preferenceと連携する将来のUI体験として整理する。0.3 Implementation Spec作成およびActivationの既存Gateは維持する。
- **0.4+:** 将来Agentが追加されても、Workspaceの表示・編集権限はOS PolicyとOwner scopeに従う。Multi-AgentのActivationは本DECで許可しない。
