# 創設者から友人へ送る文面

以下はコピーして使う文案です。ファイルの公開自体は送信・承認・権限付与ではありません。

## 1. ZIPと一緒に送る文

```text
Nagiの共同開発用の資料をまとめました。
担当としてお願いしたいのは、Nagi Developer PlatformのPT-02〜06です。アプリの雛形生成、Windows/LinuxのAPI差分、UI構造の解析・対応付け、既存ツールを使った検証、移植評価をまとめて育ててほしいです。

Nagi全体の製品方針は私が決めますが、割り当てた範囲の設計、実装方法、順番、Claude/Codexへの仕事の分け方は任せます。細部ごとに確認を取る必要はありません。PT-01や共有SDKなど、既存担当の仕事は引き継がず接続する形です。

まず00_START_HERE.mdを読んで、Claude CodeかCodexでNagiOSを開き、prompts/00_BOOTSTRAP.mdを貼ってください。最初のNDP-01で最新の担当・path・使えるSDK/ツールと開始条件をまとめてください。既に確定している条件を再確認する必要はありません。足りない承認や接続確認は一度にまとめて私へ返してください。その後は承認した担当を自律的に進めてください。

GitHubとAIは自分のアカウントを使ってください。私の認証情報やローカル環境を使う必要はありません。公開仕様の正本は Roy-To/NagiOS の docs/product-decisions/ です。
```

## 2. NDP-01後に送る一括開始承認文

**これは承認の下書きです。** NDP-01の結果と `templates/START_AUTHORIZATION.md` の内容を人間が確認し、担当・path・作業場所・統合先を実際に確定してから送ってください。未解決のPT-01/SDK接続を「確認済み」にしません。

```text
NDP-01で照合した開始条件を確認しました。START_AUTHORIZATION.mdの確定欄に記載した担当者、作業場所、branch、書込みpath、検証範囲、統合先を承認します。必要なworkstream登録・既存ownerとの接続確認は、その記録に従って反映してください。

その範囲で、PT-02〜06の割当済みNDPタスクのhost側設計・実装・テスト・修正、担当branchへのcommit/push、PR作成を開始してください。初期の実行対象と並列数も同記録のとおりです。既存0.2規則が要求するM30前host-only checkpointは、この限定範囲の承認として記録してください。既存release gateやNagi target受入を解除するものではありません。

担当内の実装方法、内部構成、作業順、テスト追加、Claude/Codexの分担は任せます。日常の作業ごとに私の承認を待たず、実装→テスト→修正→commit→次の独立タスクへ進めてください。1件が接続待ちになっても、別の承認済みタスクは進めてください。

私への相談は、製品方針・公開APIや権限の意味の変更、他担当の所有範囲への影響、新しい課金・外部送信範囲など、今回の承認に含まれない判断にまとめてください。mainへの直接push、無断merge、正式署名・配布、他人の作業物の上書きは含みません。
```

## 3. 創設者側で一度だけ決めるもの

必要なのは短い開始記録1つです。詳細な採用報告や証明書類を増やしません。

- 受取Core Developerの担当task群と、既存ownerから切り離した編集path。
- 本人が選んだ専用開発フォルダ／既存作業環境。新しいclone/worktreeが必要な場合はその範囲。
- 担当branch、PRのbase、受取Integration Owner。Linux移行branchを自動流用しない。
- 自分のforkか本体へのWriteか。アカウント確認中なら、まず公開資料の読取を進める。招待・設定変更は別操作。
- host-only checkpointと登録担当。起動していないQEMUや未提供SDKは条件充足としない。

具体的な個人情報・ユーザー名入りローカルパスは公開記録へ書かず、役割とrepository相対pathで表してください。
