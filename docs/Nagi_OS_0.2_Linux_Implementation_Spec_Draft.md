## 5. Proposed parallel execution lanes

Lanes describe handoffs, and ownership comes from the registry and explicit Integration Owner assignments. Dependency edges require the named contract or acceptance to pass; producers and consumers may prepare against versioned fixtures where separately authorized. Keep real adapters for target tests. Use shared IDL/ABI, Cargo, workflow and registry changes only at the Integration Owner checkpoint.

| Lane | Milestones | Handoff and blocking dependencies |
|---|---|---|
| A — integration and release | M00–M05, M28–M30 | Publish baseline/registry checkpoint, build-input manifest and CI/evidence format. M28 consumes accepted target lanes and M29–M30 consume reproducible, signed integrated results. |
| B — system and security | M08–M10, M13 | From frozen Linux boot and session/storage foundations, publish one caller/session + launch/IPC contract with reject/expiry/restart fixtures for C–H. Treat M08–M10 as a jointly versioned boundary, avoiding a circular milestone gate. M13 needs the D manifest contract and proves real managed app/jobs. |
| C — Settings and UI | M06–M07, M11, M14 | Publish catalog/locale/UI fixtures early. Target writes/delivery need B's caller, service lifecycle and IPC, plus settings/recovery; provide first-party consumers and accessible notification UI. |
| D — install and recovery | M12, M15 | Manifest schema shared with B, G and H precedes supervisor integration. Installer depends on verified package trust, storage journal and lifecycle. Supply failed-switch, unsafe-path and recovery evidence to A. |
| E — AI and audio | M16 + voice candidate | B's identity/IPC/jobs and F's typed action boundary precede target provider use. Publish bounded provider, cancellation and resource policy for Search and apps. Voice evaluation also needs audio and microphone policy. |
| F — common platform | M17–M20 | Freeze Resource/Action identities early after B, then Activity/Wayback, authorized indexing and Context. The M16 dependency applies to semantic provider adoption; lexical operation remains independent. |
| G — first-party apps | M22–M27 | Reuse app foundations on versioned F/H contracts and B target boundaries. Prove real common adapters, then Files/Notes, Activity/Wayback, Home/Search and Albert/Terminal consumer cases. App-focused work can progress in parallel once its own dependencies pass. |
| H — developer platform | M21 | Manifest/ABI/declared authority from B/D and layered public contracts from F. Finish SDK/fixture versioning and target out-of-tree acceptance. NDP host CI has its own evidence boundary. |

First checkpoint proposal: record the 0.1 release boundary and reconcile the registry, then confirm the B/D authority and manifest seams, A artifact identity and F public IDs. Initial contract and fixture work follows existing approvals. Once a target contract is accepted, attach the consumer's exact source, config, negative cases and output to its owning state. Integration must still run M28 and release hardening.
